# GUI 智能体技术调研报告

## 摘要

本项目面向 Windows 桌面 GUI 任务，目标是将自然语言目标转化为可审计、可中止、可复现的操作闭环。技术难点不在于单独调用视觉语言模型，而在于将屏幕感知、任务规划、受控执行和结果验证组织为稳定系统。本文比较 ScreenAgent、UI-TARS 与 WebArena 三类代表性工作，并据此确定项目采用“模型负责提出候选动作，确定性组件负责校验、执行与验证”的路线。

## 1. 问题定义

桌面 GUI 智能体需要解决五类连续问题：理解用户指令、获得当前屏幕状态、生成下一步原子动作、在正确的窗口中安全执行、依据新的观察判断是否取得进展。任一环节失败都可能导致点击偏移、输入错误、循环重试或不可逆副作用。因此，系统必须将模型的不确定性限制在建议层，而不把鼠标键盘权限直接交给模型。

```text
用户指令 → 屏幕感知 → 任务理解与规划 → 动作校验与执行 → 屏幕复核 → 结果反馈
```

## 2. 代表性方案比较

| 方案 | 核心定位 | 感知与决策特点 | 动作与反馈 | 适用价值 | 对本项目的启示 |
| --- | --- | --- | --- | --- | --- |
| ScreenAgent | 面向多步屏幕任务的智能体闭环 | 将观察、规划、执行、反思串成循环；根据失败证据重新规划 | 生成结构化动作，依据后续状态决定继续、重试或结束 | 适合研究跨页面、多步骤任务的决策过程 | 采用显式 Observe–Decide–Guard–Act–Verify–Recover 状态机，不使用不可见的自由循环 |
| UI-TARS | 面向 GUI 操作的视觉语言模型与统一动作表示 | 结合截图、文字和界面元素，在统一坐标空间内推断可执行意图 | 使用归一化坐标和原子动作；强调屏幕状态变化 | 适合解决界面多样、元素位置变化和跨应用操作 | 模型只输出元素标识或归一化坐标；物理像素换算、窗口校验与频率控制由确定性 Guard 完成 |
| WebArena | 可复现的网页任务环境与功能性评测框架 | 以可恢复初始状态和任务结果为中心，而非固定点击轨迹 | 通过任务目标是否达成评估成功，并记录失败模式 | 适合构建可比的端到端评测 | 采用受控测试窗口、可恢复初始状态和结果谓词；不将 WebArena 当作桌面控制框架 |

## 3. 技术取舍

### 3.1 分层而非端到端直控

项目不让模型直接调用鼠标、键盘或操作系统接口。模型输出受 Pydantic 约束的 `DesktopAction` 候选；Safety Guard 检查能力开关、会话锁、窗口白名单、坐标边界、动作频率、轮次预算和确认要求；Desktop Controller 仅执行已批准的 `ApprovedAction`。这种划分将难以解释的模型失误转化为可记录、可拒绝的策略决策。

### 3.2 多源感知与统一坐标

截图由 `mss` 获取，OpenCV 用于预处理和状态差分，PaddleOCR 提供文字及边界框，UI Automation 作为可选的确定性元素来源。模型和感知层统一使用相对于目标显示器的 `[0, 1]` 归一化坐标；执行层在 DPI awareness 已建立的前提下转换为 Windows 物理像素。这样能减轻多显示器、缩放比例和窗口移动造成的坐标漂移。

### 3.3 单进程、单模型的本地推理

首个原型使用 Windows Conda Python 3.12、PyTorch CUDA 13.0 与 Transformers，在 RTX 5070 Ti 上以 BF16 运行本地多模态模型。LangChain 用于提示词和模型调用封装，LangGraph 显式描述状态转移。首版避免引入 vLLM、数据库、消息队列和多 Agent 协作，以降低部署和调试复杂度；只有在吞吐、并发或跨进程状态确有需求时才扩展基础设施。

### 3.4 结果验证优先于轨迹复现

固定坐标轨迹容易受窗口布局和动态内容影响。系统为每个动作声明预期观察，由 Verifier 根据 OCR 文本、UI 状态、截图差分和任务规则收集证据。失败时 Recovery 选择等待、重新观察、重新规划或请求人工接管，而不是绕过 Guard 盲目重复操作。

## 4. 前四周的落地重点

| 阶段 | 必须形成的能力 | 对完整闭环的作用 |
| --- | --- | --- |
| 环境与技术基础 | 固定 Python/CUDA 依赖、GPU BF16 自检、模型目录、离线基准和证据归档 | 为后续模块提供可复现的运行底座与性能基线 |
| 桌面感知与控制 | 截图、OCR、OpenCV、UIA、受控点击/输入/滚动/拖拽、急停与日志 | 将真实界面状态转换为可计算观察，并提供受限执行器 |
| 数据与基础 Agent | 统一指令、截图、动作和结果字段；观察、规划、动作、反馈接口；本地模型 Provider | 使模型建议和确定性模块通过稳定契约协作 |
| 端到端集成 | CLI 入口、状态机、超时与失败退出、五项基础任务及日志 | 验证“指令—感知—规划—执行—反馈”闭环是否可复现 |

## 5. 风险与控制原则

- 坐标偏移：记录显示器矩形、DPI 比例和活动窗口边界，禁止绕过 Guard 的物理坐标执行。
- 模型输出不规范：对动作类型、坐标范围、文本字段和目标描述做结构化校验。
- 页面变化或无进展：使用状态指纹、截图差分和最大轮次限制，触发重新观察或人工接管。
- 外部副作用：仅在授权测试账户、模拟应用或专用测试窗口中运行；消息发送等操作限定测试对象。
- 性能和显存：记录模型加载时间、推理时延和显存峰值，优先缩小图像尺寸、上下文和输出长度。

## 6. 结论

ScreenAgent 说明了显式闭环和失败反思的必要性，UI-TARS 提供了视觉驱动的统一动作表示思路，WebArena 则强调可复现环境和功能性结果评估。本项目将三者的有效部分组合为受控桌面智能体：模型负责感知推理与候选动作，系统负责安全放行、执行、验证和审计。该路径适合在有限周期内先完成可靠的四周主线，再在稳定接口上扩展训练、评测和更高阶能力。
