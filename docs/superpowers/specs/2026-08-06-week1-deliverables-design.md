# 第一周文档交付设计

## 目标

面向组内 mentor 提供两份可直接审阅的 Markdown 报告，并将可复现环境说明整合进项目 README。文档以技术调研和工程落地为主，不设置参考来源章节，也不将内容按“已验证/待完成”分类。

## 交付物

1. `docs/week1/research-report.md`：比较 ScreenAgent、UI-TARS、WebArena 的问题定位、核心方法、适用范围和局限；给出本项目关于感知、规划、动作执行、验证与安全的组合式取舍。
2. `docs/week1/architecture-report.md`：覆盖完整 GUI 智能体闭环，以 Mermaid 展示端到端架构、运行边界和数据流；说明模块职责、核心数据契约、安全与异常处理。重点映射前四周的环境基础、感知与控制、基础 Agent、端到端集成。
3. `README.md`：整合 Windows 11 / Conda `max` / Python 3.12 / PyTorch CUDA 13.0 的安装、诊断、模型获取、离线基准、产物归档与故障排查步骤。

## 写作原则

- 使用中文、面向具备工程背景的 mentor，优先呈现决策、边界和下一步可执行方式。
- 将安全 Guard、受控测试环境、无隐式联网加载、模型与证据的 Git 忽略作为贯穿约束。
- 以完整系统为架构报告的组织尺度；第一至四周仅作为必须实现能力的分层落地路线，不将报告拆为周报。
- 保持与现有项目的命令、路径、模型目录和 CLI 名称一致。

## 校验

- Markdown 标题层级、代码块、表格和 Mermaid 语法可读。
- 所有命令与仓库已有 README、依赖清单和 OpenSpec 方案一致。
- 不写入模型权重、密钥、真实截图或其他敏感数据。
