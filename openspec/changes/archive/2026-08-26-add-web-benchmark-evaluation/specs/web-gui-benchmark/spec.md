## ADDED Requirements

### Requirement: 本地受控 Web 测试场

系统 SHALL 提供仅绑定回环地址的 Python Web 测试场，包含表单、文件列表和设置类可见页面。
页面 MUST 由真实浏览器渲染并接受普通鼠标、键盘和滚轮操作；服务 MUST NOT 访问外网、真实账号、
个人文件或消息服务。

#### Scenario: 浏览器展示本地表单页面
- **WHEN** 评测运行器启动测试场并打开指定表单任务路由
- **THEN** 浏览器显示可填写、保存并呈现业务结果的本地页面，且服务只监听 `127.0.0.1`

### Requirement: 任务初始状态可重置

测试场 SHALL 为每个已注册任务保存独立的初始业务状态。评测运行器调用本机重置接口时，服务
MUST 恢复任务指定的路由、表单值、列表内容、弹窗和滚动相关状态；前一次运行产生的数据 MUST
不影响下一次运行。

#### Scenario: 同一任务连续两次运行
- **WHEN** 任务在第一次运行中创建了项目，随后运行器再次重置同一任务
- **THEN** 第二次运行开始时项目列表与该任务定义的初始状态一致，且不含第一次新增项目

### Requirement: 业务状态仅供评测器读取

测试场 SHALL 通过仅限本机的状态接口返回完成评分所需的最小业务状态。该状态接口及重置接口
MUST 不在任务页面中展示、链接或通过 Agent 工具暴露；页面也 MUST NOT 直接显示任务答案或成功
断言。

#### Scenario: Agent 只能经 GUI 完成任务
- **WHEN** Agent 执行一条本地 Web 任务
- **THEN** Agent 仅通过现有截图和桌面键鼠工具与浏览器页面交互，评分状态仅由评测运行器读取

### Requirement: 可见交互覆盖基准任务类型

测试场 MUST 提供能够覆盖点击、文本输入、选择、滚动、多步骤保存、表单校验、确认弹窗和布局
变化的可见交互。用户动作成功或失败后，页面 MUST 呈现与内部业务状态一致的后续界面。

#### Scenario: 校验错误后修正并保存
- **WHEN** Agent 在必填表单未填完整时点击保存，然后补全字段并再次保存
- **THEN** 页面先显示校验错误，后显示保存后的业务结果，状态接口反映最终保存值
