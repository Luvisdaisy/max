# agent-task-evaluation Specification

## Purpose

通过本地、可审计且可重置的 GUI 任务集评估 Agent，报告基础模型与 LoRA 模型在一致实验条件下的原子指标与逐题证据。
## Requirements
### Requirement: 显式启动的固定规模自动评测

系统 SHALL 保留 `max-gui --benchmark` 入口，启动仅绑定回环地址的评测首页。首页 MUST 显示「运行 10 条」
与「运行 100 条」按钮；只有用户点击其中之一后，系统才可使用当前 `.env` 模型配置启动浏览器并顺序
执行所选批次。页面 MUST 显示所选总数、当前任务、进度和终态报告路径，评测运行中再次启动 MUST 被拒绝。
评测运行时，用户按 Escape MUST 请求中断当前批次；系统 MUST 中断当前 Agent、停止后续题目、保留已完成
结果并以 `interrupted` 终态显示报告路径。

#### Scenario: 点击 10 条入口后运行冒烟任务集

- **WHEN** 用户以 `max-gui --benchmark` 启动评测首页并点击「运行 10 条」
- **THEN** 系统重置并依次执行固定的 10 条分层任务，页面显示进度，全部结束后写入标明 10 条范围的报告

#### Scenario: 按 Escape 中断运行中的批次

- **WHEN** 10 条或 100 条批次正在运行且用户在评测场页面按下 Escape
- **THEN** 系统中断当前 Agent、停止后续任务，并将已完成任务写入终态为 `interrupted` 的报告

### Requirement: 版本化任务定义

系统 SHALL 从版本化任务定义加载恰好 100 条显式且互不复制的 GUI 评测任务。每条任务 MUST 包含唯一
标识、页面路由、自然语言指令、初始状态、成功断言、禁止动作、工具调用上限、超时、easy/medium/hard
难度和能力标签；任务集 MUST 覆盖单一操作、同页组合、多步骤工作流和鲁棒性任务。

#### Scenario: 加载完整 v2 任务集

- **WHEN** 评测运行器加载 v2 任务集
- **THEN** 任务集含恰好 100 条显式任务，覆盖三种难度和规定能力标签，且不通过复制模板扩展任务数

### Requirement: 独立状态断言评分

评测运行器 SHALL 在每题终止后读取测试场业务状态并逐项检查成功断言。全部断言满足时 MUST
记为严格成功；仅部分满足时 MUST 报告通过断言数和部分完成率，且 MUST NOT 计入严格成功率。
Agent 的最终文本不得单独构成任务成功。

#### Scenario: 部分完成不计严格成功

- **WHEN** 创建项目和待办成功，但待办优先级未达到任务要求
- **THEN** 结果记录已通过和总断言数，严格成功为否，任务不计入成功率分子

### Requirement: 明确任务终止条件

评测运行器 MUST 在 Agent 到达终态、超过任务超时、超过工具调用上限或触发禁止动作时终止当前题。
超时、上限、Agent 错误、中断和违规 MUST 在结果中使用可区分的终止原因；环境准备失败 MUST 单独
报告，且 MUST NOT 计入模型任务失败率。

#### Scenario: 工具调用超过上限

- **WHEN** 一条任务的工具调用次数超过其定义上限
- **THEN** 运行器停止该任务，结果终止原因为工具调用上限，严格成功为否

### Requirement: 可审计原子指标报告

评测运行器 SHALL 为每个任务输出 JSON 结果，并为整次评测输出 JSON 和 Markdown 汇总。结果
MUST 包含任务标识、任务集版本、模型标识、严格成功、断言进度、终止原因、执行时间、工具调用数、
工具失败数、无效动作数、违规记录和已知 Token 用量；未知 Token 用量 MUST 保留为 `null`。汇总
MUST 分别报告任务成功率、部分完成率、平均执行时间、平均工具调用数、工具失败率、无效动作率、
违规率和已知 Token 用量，MUST NOT 以不透明综合分替代这些指标。

#### Scenario: 已知与未知 Token 用量并存

- **WHEN** 一次评测中部分运行日志含 Token 用量、部分运行日志不含该字段
- **THEN** 单题未知值为 `null`，汇总只基于已知值报告 Token 用量，并标明已知样本数

### Requirement: 模型对比保持实验条件一致

系统 SHALL 支持在同一任务集上分别运行基础模型与 LoRA 模型。对比运行 MUST 使用相同任务定义、
初始状态、浏览器条件、系统提示、工具协议、迭代上限、超时和温度；报告 MUST 记录模型配置与每题
结果，便于复核。

#### Scenario: 生成基础模型与 LoRA 对比报告

- **WHEN** 使用同一任务集运行基础模型和 LoRA 模型
- **THEN** 报告分别给出两者的原子指标和每题结果，并标注一致的任务集版本及执行限制

### Requirement: 执行期工具预算与策略护栏

评测运行器 SHALL 在每个工具请求执行前检查任务定义的工具预算和禁止动作。达到预算或请求禁止动作时，
运行器 MUST 阻止该请求、请求中断当前 Agent，并将任务以可区分的 `tool_limit` 或 `violation` 终态写入结果。
被阻止的动作 MUST 不改变 WebArena 业务状态。

#### Scenario: 工具调用达到上限

- **WHEN** Agent 请求的下一次计费动作将超过该任务的工具上限
- **THEN** 该动作不执行，当前题停止，结果记录 `tool_limit` 与已发生动作数

### Requirement: 隔离且可复现的浏览器条件

评测运行器 SHALL 为每题使用临时、无账号的专用 Chrome profile，并固定窗口尺寸、缩放、语言和统一起始页。
启动器 MUST 在调用 Agent 前确认浏览器与页面可观察，并在题目结束后清理临时 profile。

#### Scenario: 连续两题浏览器隔离

- **WHEN** 第一题改变浏览器本地状态后开始第二题
- **THEN** 第二题使用新的 profile 和统一起始页，不继承第一题的标签页、缓存或页面状态

### Requirement: 可解释且不伪造未知值的评测报告

报告 SHALL 保存运行 manifest，并分别统计计划题、已执行题、环境错误、终止原因、难度、能力与任务族结果。
未知 Token 用量 MUST 在单题保留为 `null`，汇总 MUST 同时报出已知样本数和已知样本 Token 总量，且不得将
未知值计为零。

#### Scenario: 混合已知与未知 Token 用量

- **WHEN** 同一批次中只有部分任务具备 Token 用量
- **THEN** 报告保留未知任务的 `null`，并只用已知任务计算 Token 汇总与样本数
