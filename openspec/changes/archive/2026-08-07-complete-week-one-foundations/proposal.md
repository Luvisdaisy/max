## Why

第一周的运行环境已经具备基础诊断实现，但它不能验证桌面感知与控制依赖，也只输出难以快速判断的原始结果。进入第二周前需要提供一个安全、清晰且可归档的环境与基础工具核验入口。

## What Changes

- 将环境检查入口从 `--diagnose`、`diagnose` 与 `/diagnose` 重命名为 `--doctor`、`doctor` 与 `/doctor`，并将 GPU、基础工具和受控桌面最小示例验证纳入同一流程。
- 以分组的通过、失败和跳过结果替换难以阅读的原始诊断输出，同时保留机器可读的证据记录。
- 补齐第一周周报，将调研、架构、Doctor 环境核验、已知限制及第二周接口前置条件连接为可审阅的交付记录。
- 统一 README、环境指南和命令帮助所引用的 Doctor 验证顺序与证据位置。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `runtime-bootstrap`: 提供安全、易读的 Doctor 环境与基础工具验证，并明确其复现路径与证据位置不涉及任何模型信息。

## Impact

- 影响 `src/max_agent/` 的命令行、聊天命令分发、诊断与归档辅助代码、相应单元测试，以及 README 与 `docs/` 中的第一周材料。
- 不增加常规桌面控制、聊天模型调用、网络服务或新的第三方运行依赖；受控测试窗口中的桌面输入仅由显式 Doctor 探针触发。
- Doctor 的证据仅记录运行时与工具检查结果，不记录模型型号、模型目录、远程修订、文件集合或其身份摘要。
