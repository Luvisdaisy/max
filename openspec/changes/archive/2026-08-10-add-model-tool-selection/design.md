## Context

现有 `AgentOrchestrator` 按固定阶段调用注册工具，并通过摘要函数剔除图像；`ObserveScreenTool` 已能返回内存 `PIL.Image`，`LocalChatRuntime` 仅生成文本。该变更把模型的工具选择限制在注册表提供的只读感知工具范围内，优先验证桌面截图解释。

## Goals / Non-Goals

**Goals:**

- 让模型基于目标和工具描述产生一次结构化工具选择，并由编排器验证后执行。
- 在内存中把截图观察交给本地视觉模型，返回可审计的文本解释和脱敏回执摘要。
- 保持默认工具注册表、模型加载和测试均可独立注入。

**Non-Goals:**

- 不允许模型调用鼠标、键盘、窗口激活、文件写入、网络或下载工具。
- 不实现自由循环、多轮自主任务、远程 API、截图落盘或模型自动选择。
- 不保证仓库中每个模型都兼容视觉输入或可装入当前显存。

## Decisions

### 使用结构化工具选择协议而非自由文本解析

模型输出仅包含工具名称和 JSON 参数，编排器在注册表边界验证；每次解释最多允许一次工具调用。这样模型拥有选择权，但不能突破工具权限或无限重试。

备选的自由文本命令会让模型输出直接触发副作用，无法可靠校验。

### 图像只走内存中的视觉解释通道

工具回执保留图像供紧随其后的视觉解释使用；`StepRecord`、结果和归档仍只存脱敏摘要。视觉调用完成后不保留截图引用。

备选的截图文件中转会扩大敏感数据持久化范围。

### 在普通聊天中执行一次受限工具循环

普通用户消息先进入模型；模型可选择不调用工具，或在工具白名单内发起一次结构化调用。成功观察后，将内存图像和回执输入同一模型继续推理并生成最终回复。前端只显示最终文本，不把截图或工具原始数据写入聊天记录。

备选的独立命令会把工具使用从自然对话中割裂，不能验证用户提出桌面描述需求时的自主工具选择。

## Risks / Trade-offs

- [所选模型不支持图像或显存不足] → 返回本地视觉能力错误，用户可用 `/model` 改选模型。
- [桌面截图含敏感内容] → 不落盘、不进入日志或结果；仅在当前进程内供模型调用。
- [模型请求越权工具] → 白名单、注册表参数校验和一次调用预算共同拒绝。

## Migration Plan

1. 为模型工具选择协议、只读权限筛选和内存图像脱敏增加测试。
2. 接入默认注册表、LangGraph 编排路径与本地视觉解释适配。
3. 将普通聊天接入受限工具循环和文档，并在可用视觉模型条件下手动验证当前桌面解释。
4. 运行全量测试、静态检查、依赖检查和 OpenSpec 严格校验；回退时移除演示入口并保留现有只读感知工具。
