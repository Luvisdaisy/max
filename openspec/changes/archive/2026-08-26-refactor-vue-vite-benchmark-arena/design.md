## Context

现有评测场由 Python 路由直接拼接 HTML，业务页面仅包含表单、文件列表和设置，并从 20 个模板复制为
100 条任务。运行器、任务重置、独立评分、报告和首页的 10/100 条选择已在 Python 中存在，且必须继续
保持仅经真实浏览器截图和键鼠评测的安全边界。

本变更把可见业务 UI 重构为 Vue + Vite，同时以 FastAPI 托管构建产物，保持单进程、回环地址和本地
控制接口。旧版页面与任务文件无需兼容或迁移。

## Goals / Non-Goals

**Goals:**

- 交付由 Vue 渲染的多页面本地评测场，以及 FastAPI 单进程生产入口。
- 以 100 条显式、唯一任务替代复制展开；每条任务都可独立重置和断言评分。
- 定义 easy、medium、hard 的可检查覆盖标准，并保留稳定的 10 条分层冒烟批次与完整 100 条批次。
- 保持 Agent 不可见状态/重置接口、回环限制、真实浏览器键鼠执行和既有报告语义。

**Non-Goals:**

- 不提供旧 `/form`、`/files`、`/settings` 页面、`web-gui-v1` 或任务迁移工具。
- 不增加联网、真实账户、DOM 自动化、并行评测、随机抽样或任意任务数量入口。
- 不将 Vite 开发服务器作为 `max-gui --benchmark` 的运行依赖，也不修改 Agent 工具协议或模型评测指标。

## Decisions

### Vue 构建产物由 FastAPI 单进程托管

前端独立位于仓库的 `frontend/benchmark-arena/`，通过 Vite 构建为静态产物；Python 服务在生产评测时
托管该目录并对业务路由回退至入口 HTML。开发时允许 Vite 热更新服务器，但 `max-gui --benchmark` 只启动
FastAPI/uvicorn 一个进程。相比运行两个服务，此方案保留现有 `127.0.0.1` 安全边界和启动方式；相比继续
服务端拼接 HTML，Vue 能清晰管理多页状态、反馈与可见交互。

### 后端为唯一可判分状态源，前端只经业务 API 操作

每次 `/api/reset` 在后端按任务初始化状态并返回 Agent 可见的业务路由；Vue 通过业务 API 读写当前状态。
`/api/state` 只向运行器返回最小评分状态，既不在 UI 中链接，也不返回给业务 API。前端不得内嵌成功
断言或任务答案。这个分界避免客户端状态伪造，同时让每题重置仍是确定性的。

### 统一起始页与站内导航

每条任务重置后只返回统一的 `/arena/home` 起始页。Vue Router 提供工作台、收件箱、项目、任务、日历、
自动化、团队、报表和设置视图，Agent 必须点击侧边栏、面包屑或实体详情链接完成页面切换。运行器不得
按任务目标拼接或打开业务路由。前端每次站内导航通过业务 API 记录 `visited_pages` 与导航来源，评分可
要求出现必要页面检查点；地址栏直接跳转不计为有效导航检查点。

### 难度同时约束动作长度与工作流结构

任务定义增加 `expected_steps` 与 `required_checkpoints`。easy 需要 1 至 3 个主要可见操作并保持单目标；
medium 需要 5 至 6 个主要可见操作，并组合至少两种能力或包含一次站内导航；hard 需要 7 个以上主要
可见操作、至少一次跨页，并包含状态依赖、检索、确认、批量、动态反馈、视觉判断或错误恢复中的至少
一项。动作数只描述推荐最短路径，不要求 Agent 严格按固定轨迹执行。

### 以业务结果而不是动作代号评分

后端状态保存项目、任务、成员、自动化规则等业务实体，以及导航与交互检查点。每条任务的 `success`
断言直接比较实体最终值或检查点集合，不再使用任务 ID 伪装 `last_action`。任务指令只描述用户目标，
不得出现“本题对象为”、内部任务 ID、断言字段或推荐操作轨迹。

### 任务集采用显式 100 条记录与可验证覆盖矩阵

任务文件不含 `copies_per_template`、变体扩展或同一工作流的同构复制。每条任务具有不同的操作目标或
状态组合；加载器拒绝少于 100 条、重复 ID、缺失难度，及任何复制展开字段。任务按 easy、medium、hard
定义配额并覆盖输入、选择、筛选、滚动、分页、编辑、批量、确认、校验恢复和跨页状态依赖。相比随机
生成或模板扩展，显式记录可审计、可复现且能评审任务差异。

### 保留固定 10/100 选择，但以难度与能力覆盖选择冒烟集

完整入口始终返回 100 条。10 条入口从 v2 任务集中稳定选择覆盖三种难度和关键交互类型的任务，选择
结果由测试固定。相比仅按前三个难度配额选择，覆盖矩阵能避免冒烟集集中在同一业务页面。

### Escape 中断整次批次

Vue 首页在评测运行时监听 Escape，并调用仅限本机的中断接口。控制器记录中断请求、转发给当前
`AgentRunner.interrupt()`，并在当前题终态后停止后续任务；已收集结果仍写入带请求规模的报告，首页终态
显示 `interrupted` 和报告路径。相比直接终止进程，这能保留可审计结果并让浏览器与本地服务保持可继续使用。

### 一次性切换并删除旧评测场

实现完成时删除服务端 HTML 辅助函数、旧业务路由、旧 JSON 与专属测试；不保留兼容路由或双写状态。
在一次变更内更新 Python 加载器、前端、文档、测试和依赖锁文件。这样避免 Agent 或维护者误用旧任务集。

## Risks / Trade-offs

- [前端构建依赖增加 Node.js 工具链] → 在文档与 CI 中明确 Node 版本、`npm` 脚本和构建检查；运行时只需构建产物。
- [前后端状态脱节造成评分不一致] → 以后端状态为唯一真源，并为重置、业务 API 和判分加入端到端合同测试。
- [100 条手工任务难以证明不重复] → 增加任务 ID、操作目标、状态断言与能力标签的唯一性/覆盖验证。
- [删除旧场地后历史脚本失效] → 同步更新 `max-gui --benchmark` 路径和开发文档；不承诺旧路由兼容。
- [前端路由回退掩盖缺失页面] → 测试每条任务路由都可渲染对应可见页面，并拒绝未知业务路由。

## Migration Plan

1. 创建 Vue + Vite 工程、构建脚本与静态产物托管骨架，同时定义后端业务 API 和 v2 状态模型。
2. 实现全部业务页面与 100 条显式任务，先以合同测试验证重置、路由、状态和评分。
3. 将运行器和 10/100 选择切换至 v2，增加前端构建与浏览器级验证。
4. 删除旧 HTML 页面、旧路由、`web-gui-v1.json`、模板扩展逻辑和失效依赖/测试，更新说明。
5. 若切换出现回归，在未删除旧场地前可回退提交；完成删除后，以版本控制回退，不在产品中保留双实现。
