## Why

当前任务胶囊已经能保存计划、最近截图、短期事实和完成核验，但不能以结构化方式稳定表达当前前台应用、窗口、焦点与弹窗，也没有逐动作的预期结果。模型仍需从截图和自然语言推断“当前在哪”和“刚才是否生效”，这会削弱跨应用与文件选择等真实桌面流程的稳定性。

本变更以轻量、带时效的状态层补足这些信息，同时保留现有“当前帧才可执行”和独立后置观察的安全边界。

## What Changes

- 新增基于最新观察帧的结构化桌面观察快照，记录前台应用、前台窗口、焦点元素、活动弹窗与有限 UI 候选；不可确定的信息明确为空，不得猜测。
- 在任务胶囊中新增可验证的逐动作预期与进度项；只有后置观察满足预期时，才可推进对应进度，无法验证时保留待验证状态并给出恢复信息。
- 将现有计划、近期动作、截图绑定事实、完成声明与完成核验收敛到统一的状态更新／失效规则；新截图、桌面副作用、任务边界与恢复均不得复用过期可执行对象。
- 持久化可恢复且脱敏的状态摘要，兼容旧会话和 checkpoint；不写入完整无障碍树、OCR 正文、坐标或键盘输入正文。
- 将状态摘要注入模型上下文，并让桌面工具根据当前帧状态执行既有门禁；本变更不自行引入直接 Accessibility 点击，后续语义 UI 后端仍须保留后置观察与完成核验。

## Capabilities

### New Capabilities

- `desktop-state-layer`: 当前桌面观察、动作预期、进度和时效规则的最小状态模型。

### Modified Capabilities

- `react-agent`: 在 ReAct 循环中创建、更新、失效并注入结构化状态，且用预期验证推进进度。
- `session-store`: 持久化并安全恢复脱敏的任务状态摘要。
- `desktop-gui-tools`: 让既有桌面动作使用最新观察状态，但不改变当前截图、移鼠与点击核验门禁。
- `completion-evidence-verification`: 将任务完成的独立后置观察接入通用动作预期和进度终态。

## Impact

主要影响 `src/max_gui/agent/context.py`、`state.py`、`graph.py`、`session/store.py`、桌面观察与工具层，以及状态恢复、预期验证和多应用流程测试。不新增外部服务或长期数据库。
