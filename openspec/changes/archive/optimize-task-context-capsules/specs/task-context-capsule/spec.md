## ADDED Requirements

### Requirement: 每个用户任务拥有最小推理上下文胶囊
系统 MUST 为每个非恢复的用户文本提交创建独立任务胶囊。胶囊 MUST 包含任务标识、原始用户指令、
状态、计划与当前子任务、最新观察引用，以及受限的近期动作摘要。一次 `think` 的模型输入 MUST 从
该胶囊而非整个 `Session.messages` 构建；固定 GUI system 提示仍由现有机制注入。会话全量消息不得因
未进入胶囊而删除。

#### Scenario: 新任务不重放旧任务消息
- **WHEN** 同一会话中一个已完成任务之后提交新的普通用户指令
- **THEN** 新任务首个 think 包含新指令与新任务胶囊，且不包含已完成任务的助手正文、工具结果或截图摘要

#### Scenario: 任务内保留当前指令
- **WHEN** 一个任务已经执行多个 Think／Act／Observe 循环
- **THEN** 后续每次 think 都包含该任务的原始用户指令

### Requirement: 近期动作历史有固定上界且不泄露键入正文
任务胶囊 MUST 最多保留 6 条已完成的近期动作摘要，并按发生顺序表示工具名、截断参数、结果状态、
是否产生新观察与简短核验结论。`keyboard_type` 摘要 MUST NOT 包含输入正文，仅可记录字符数。早于上限
的动作 MUST 继续保存在会话和运行日志中，但 MUST NOT 默认进入后续模型请求。

#### Scenario: 长任务动作摘要滚动
- **WHEN** 同一任务已完成第 7 条工具动作
- **THEN** 胶囊只保留最近 6 条动作摘要，而会话 JSON 仍保留全部 7 条工具消息

#### Scenario: 键入文本不进入摘要
- **WHEN** 任务执行 `keyboard_type` 并构建后续 think 上下文
- **THEN** 动作摘要不含该工具的输入正文

### Requirement: 最新有效观察是唯一内联图像
任务胶囊 MUST 至多选择一张仍存在的图像内联给模型。优先选择本任务最近一次成功 screenshot 的图像；
若不存在，选择本任务最近的有效用户附件；若仍不存在，模型上下文 MUST 明确无当前图像，且桌面动作
继续受现有截图前置约束。旧任务图片和同任务更早图片 MUST NOT 以内联图像形式进入请求。

#### Scenario: 动作后的截图覆盖旧图
- **WHEN** 本任务已有初始截图，随后桌面动作产生新的成功截图
- **THEN** 下一次 think 仅内联动作后的截图

#### Scenario: 没有任何有效图像
- **WHEN** 新任务没有附件且尚未成功截图
- **THEN** 首次 think 没有 `image_url`，并仍能依据 GUI system 契约调用 screenshot

### Requirement: 恢复只续接中断任务
系统 MUST 仅在用户明确恢复一个带 checkpoint 的 `interrupted` 任务时续用该任务胶囊和 `run_id`。
其它新的用户文本 MUST 创建新任务胶囊，即使它处于同一会话。缺少胶囊字段的旧 checkpoint MUST 仍按
既有中断恢复语义运行，并在下次持久化时写入可用的新胶囊数据。

#### Scenario: 中断后恢复保留当前任务
- **WHEN** 用户恢复一个中断的桌面任务
- **THEN** 后续 think 使用该任务的原始指令、当前计划、近期动作和最新观察，而不新建任务标识

#### Scenario: 新指令结束旧任务上下文
- **WHEN** 会话存在已完成或失败任务，用户提交另一条普通指令
- **THEN** 系统为新指令创建新的任务标识，且不把旧任务完整消息放入模型输入

### Requirement: 工具调用链作为不可分割的上下文单元
在同一任务内，编码给 OpenAI 兼容端点的 assistant `tool_calls` 与对应的 `tool` 消息 MUST 保持
`tool_call_id` 配对且顺序合法。上下文裁剪 MUST 以完整调用链为单位；不得保留一个 tool 消息而丢失其
对应的 assistant 调用，也不得保留调用而丢失已提交的结果。

#### Scenario: 裁剪后工具协议仍合法
- **WHEN** 任务的近期上下文包含至少一次已完成工具调用
- **THEN** 每条发送的 tool 消息都能在前序 assistant 消息中找到同一 `tool_call_id` 的调用
