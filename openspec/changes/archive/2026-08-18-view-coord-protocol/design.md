## Context

`view_to_logical` 把模型给的整数当视图像素，按 `logical/view` 比例换算后再 `clamp_point` 到主屏。视图高 864 时 `y=950` 会换到屏幕外并夹到最后一行，工具仍返回成功，正文还写逻辑 `(888, 1079)`。4B 下一轮把这组逻辑数再当视图像素，二次放大。换算层没坏，协议在奖励瞎猜。

约束：不改后端坐标系；`ocr_locate` 的 `target_id` 仍走逻辑中心；无截图时仍当逻辑像素。

## Goals / Non-Goals

**Goals:**

- 有视图帧时，图外坐标直接失败，模型能看见视图宽高。
- 成功动作的模型可见文案只含视图像素，避免二次换算。
- 换算后因取整超出主屏时仍夹紧，但必须说明。

**Non-Goals:**

- 网格、相对光标、区域放大、图标 spotting、开应用命令。
- 改 `screen_info` 的逻辑字段。
- 提高模型一次点准的能力（那是下一档视觉辅助）。

## Decisions

### 1. 先校验视图，再换算，最后才夹主屏

有 `ViewFrame` 且走 `x`/`y`（不是 `target_id`）时：若 `x` 或 `y` 不在 `[0, view_width) × [0, view_height)`，抛 `ToolError`，中文说明给出的点与当前 `view_width×view_height`。不调用后端。

无视图帧：保持现状，输入当逻辑像素，夹紧到主屏。

`target_id`：跳过视图校验，命中后只做主屏夹紧。

备选：继续夹紧并加警告。否决原因：会话里夹紧被当成「点到了」，模型不会改策略。

### 2. 摘要只写视图像素

`mouse_move` / 点击 / 拖拽 / 滚动成功后，正文坐标用「视图像素 (vx, vy)」。`vx, vy` 为**实际落点**再换回当前视图（夹紧后的逻辑点经 `logical_to_view`）。可保留「已从视图像素换算」「换算后已夹紧到屏幕内」「按定位编号」「尚无截图，按逻辑像素」。禁止在该摘要中出现逻辑分辨率数字。后置截图 JSON 不变（已是 `coordinate_space=view`）。

尚无截图时摘要仍是逻辑像素，并保留「尚无截图」说明（此时没有视图可报）。

备选：摘要同时写两套坐标并标注。否决原因：4B 已经混淆过一次，少露一套更安全。

### 3. 拖拽两端都要在视图内

`mouse_drag` 的 `(x1,y1)` 与 `(x2,y2)` 均须通过同一视图校验，任一端出界则整次拒绝、不拖。

### 4. 契约补一句，不新工具

`GUI_SYSTEM_PROMPT` 第 2 条改为明确：坐标必须落在最近一帧 `view_width`×`view_height` 内；工具返回的动作坐标也是视图像素，不要用 `screen_info` 或摘要里曾经出现过的逻辑分辨率去点。

## Risks / Trade-offs

- [模型经常估出图外，失败次数增加] → 这是目标；错误文案给出视图尺寸，促使其重看图或改用 `ocr_locate`。
- [取整后合法视图像素仍夹到屏幕边] → 仅保留这一类夹紧，并写明。
- [旧测试断言逻辑坐标] → 改为断言视图像素与出界错误。
- [无字图标仍只能猜] → 本期不解决；出界失败至少不会点到 Dock 底边冒充成功。

## Migration Plan

- 无数据迁移。旧会话坐标帧仍可用。
- 回滚：恢复出界夹紧与逻辑坐标摘要。

## Open Questions

无。网格与相对点击留待后续 change。
