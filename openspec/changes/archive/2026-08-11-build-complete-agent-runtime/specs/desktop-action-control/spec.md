## Purpose

为 Agent 生成的候选桌面动作提供确定性的审批与执行边界，确保默认可操作电脑的运行时仍只能对当前授权目标发送有限、可验证的输入。

## ADDED Requirements

### Requirement: 动作与窗口身份审批
每个可能发送桌面输入的候选动作 MUST 在执行前经过审批。审批 SHALL 校验动作类型、字段组合、目标元素或坐标、当前前台状态以及目标窗口的句柄、进程标识和已解析可执行路径；窗口标题不得单独作为授权依据。审批后任一身份或画面状态变化 MUST 使批准失效并要求重新观察。

#### Scenario: 审批当前有效目标
- **WHEN** 候选动作引用当前观察中可见元素，且窗口身份、坐标和策略均有效
- **THEN** 系统产生绑定当前状态指纹和窗口身份的批准动作

#### Scenario: 窗口在审批后变化
- **WHEN** 执行前的窗口身份、前台状态或观察指纹不再匹配批准动作
- **THEN** 执行工具拒绝旧批准、返回可恢复失败并且不发送输入

### Requirement: 有限桌面动作空间
执行工具 SHALL 仅支持窗口激活、点击、双击、Unicode 文本输入、滚动、拖拽、等待和策略白名单中的按键组合。工具 MUST NOT 提供命令行执行、任意脚本、文件删除、注册表修改、进程终止、剪贴板读取或网络请求能力。

#### Scenario: 执行白名单动作
- **WHEN** 批准动作属于允许的动作类型且所有约束在执行时仍成立
- **THEN** 执行工具发送最小必要输入并返回包含动作哈希、时间和结果的结构化回执

#### Scenario: 请求未授权能力
- **WHEN** 候选动作要求任意脚本、非白名单按键组合或其他未公开能力
- **THEN** Guard 返回 `POLICY_DENIED`，执行工具不被调用

### Requirement: 坐标和焦点安全
所有模型坐标 MUST 在审批阶段解析为目标显示器的物理像素，并位于当前授权窗口或明确允许的系统表面内。窗口激活、点击和文本输入前 MUST 再次确认前台窗口和焦点；无法确认时不得回退到盲目坐标输入。

#### Scenario: 转换有效观察坐标
- **WHEN** 候选动作引用当前屏幕观察中的元素边界或归一化坐标
- **THEN** Guard 依据对应显示器边界和 DPI 元数据生成物理坐标并验证命中目标范围

#### Scenario: 输入焦点丢失
- **WHEN** 文本输入或按键组合执行前焦点不在批准的目标窗口或元素
- **THEN** 系统中止本次动作、释放输入状态并重新观察，不向其他窗口发送文本

### Requirement: 高影响动作与人工确认
发送、提交、保存、覆盖、删除、支付、凭据输入、关闭未保存内容及其他策略标记的高影响动作 MUST 进入 `WAITING_USER`，并以绑定动作、窗口身份和当前状态指纹的摘要请求确认。确认超时、拒绝或状态变化 MUST 阻止执行。

#### Scenario: 普通记事本追加
- **WHEN** 用户已明确提供要追加的文本且动作仅修改当前记事本未保存缓冲区
- **THEN** Guard 可按普通文本输入审批，无需额外启用桌面控制参数

#### Scenario: 请求保存文件
- **WHEN** Agent 计划保存、覆盖或另存记事本文档
- **THEN** 系统在执行保存相关输入前请求用户确认，未确认时保持文档缓冲区且不写入文件

### Requirement: Fail-safe 与输入状态释放
执行期间系统 MUST 启用本地 Fail-safe 和用户中止通道。成功、失败、超时、取消、异常和进程退出路径 MUST 统一释放鼠标按键与修饰键；触发 Fail-safe 后不得自动恢复执行。

#### Scenario: 用户触发 Fail-safe
- **WHEN** 执行期间检测到配置的鼠标角落或紧急快捷键
- **THEN** 当前任务转为 `ABORTED`，立即释放输入状态并停止所有后续动作

#### Scenario: 执行库抛出异常
- **WHEN** 桌面输入适配器在动作中抛出异常
- **THEN** 工具返回 `ACTION_ERROR`、执行统一输入清理，并且不得自行重试相同动作
