## Context

见 `proposal.md`。当前 `src/max_agent/` 尚未实现屏幕感知、工具注册表或 Agent 编排器；`tech-design.md` 中的这些内容是后续实现设计。现有 `doctor --desktop-probe` 已使用临时 Tk 窗口并在发送输入前比较 Windows 前台窗口句柄，但它只调用 Tk 的焦点方法；Windows 11 不保证这会改变操作系统前台窗口，导致探针安全地跳过。

## Goals / Non-Goals

**Goals:**

- 把未来感知实现的唯一代码位置确定为 `src/max_agent/tools/perception/`，使其与模型、桌面执行、安全、验证、恢复和归档工具同属工具边界。
- 让显式桌面探针先有限地请求自身临时窗口成为前台，再进行现有的句柄确认；不能确认时保持无输入跳过，并给出可理解的下一步。
- 同步 `tech-design.md` 与 `AGENTS.md` 中的目录和验证命令。

**Non-Goals:**

- 不创建空的 `tools`/`perception` 包或虚假的工具实现；实际感知功能开始实现时再创建对应模块。
- 不移动现有诊断、模型或控制台模块，不实现 Agent 编排器、OCR 推理或桌面控制功能。
- 不让 Doctor 在默认模式下改变前台窗口或发送任何桌面输入。

## Decisions

### 感知置于 `tools/perception`

未来目录采用 `tools/base.py`、`tools/registry.py` 与 `tools/perception/` 的组合。`perception` 仅按 `observe_screen`、`recognize_text`、`detect_ui_elements` 等独立工具组织；编排器经注册表调用这些工具并消费回执。

选择它而不是顶层 `perception`，因为它让目录结构表达统一的工具权限、超时、输入/输出和审计契约。选择它而不是把所有感知文件平铺在 `tools/`，因为感知实现会共享截图、坐标和观察结果类型，子目录能避免命名和职责混杂。

### 显式探针可请求前台，但不绕过确认

仅在 `--desktop-probe` 下，调用 Windows 前台窗口 API 请求临时 Tk 窗口置前；随后复用句柄比较作为唯一的输入放行条件。Windows 仍可拒绝该请求，因此探针不能将 API 调用视为成功，也不能重试、抢占其他应用或在未确认时发送输入。

选择此方案而不是删除探针，因为库导入、屏幕尺寸和内存截图不能验证真实键盘/鼠标事件是否被受控目标接收。选择它而不是将前台失败视为错误，因为远程、锁屏、自动化宿主和 Windows 前台策略下该情况是正常且安全的能力限制。

## Risks / Trade-offs

- [Windows 仍拒绝前台请求] → 保留跳过语义，明确未执行输入测试和交互式重试条件。
- [前台请求干扰用户] → 仅作用于本进程刚创建的临时窗口，且只在用户显式传入 `--desktop-probe` 时执行。
- [设计目录被误当作已实现能力] → 技术报告明确当前没有需要迁移的感知模块，且不创建空包。

## Migration Plan

1. 更新技术报告与协作说明，锁定未来目录边界和 `doctor` 命令。
2. 先以单元测试覆盖“请求后仍需句柄确认”和“失败时无输入的跳过提示”。
3. 在显式探针中加入最小的 Windows 前台请求，保持现有清理和输入守卫。
4. 运行单元测试、`pip check` 与默认/显式 Doctor；仅在交互式 Windows 会话可用时，人工确认受控输入路径。
