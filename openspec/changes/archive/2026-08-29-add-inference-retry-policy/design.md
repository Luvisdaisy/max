## Context

`InferenceClient.stream` 当前只发起一次 OpenAI 兼容流式请求。连接、超时和 HTTP 非 2xx 都直接转成异常；`AgentRunner._think` 捕获后立即发出 `model.failed`，把图和会话置为 `error`。工具消息在每次动作后已经增量持久化，因此重试推理请求不能重放已成功工具，也不能把一次网络尝试算成新的 ReAct 迭代。

本变更面向全部主推理 provider，当前主要故障样本来自 WSL Ollama：同一任务前几轮成功，后续 `/v1/chat/completions` 返回缺少有效正文的 400，服务随后又可能不可达。HTTP 400 既可能是永久请求错误，也可能是上游网关或服务异常，不能一律重试或一律立即失败。

## Goals / Non-Goals

**Goals:**

- 一次逻辑模型调用在瞬时故障下，首次失败后最多自动重试 5 次。
- 用明确、可测试的分类避免重试鉴权、模型不存在、上下文超限和 schema 错误。
- 保持流式输出、会话消息、ReAct 迭代和桌面工具副作用幂等。
- 让用户从 TUI 与 JSONL 看见重试次数、原因、等待时间和最终结果。
- 在退避等待期间及时响应用户中断。

**Non-Goals:**

- 不重试 `registry.invoke` 或任何桌面工具，不补偿已经发生的桌面副作用。
- 不自动修改请求字段、删减工具 schema、缩图、切换模型或切换 provider。
- 不用重试掩盖稳定复现的协议错误，也不新增熔断器、健康检查守护进程或外部队列。
- 不保证流已经输出有效增量后的透明续传。

## Decisions

### 1. 在推理客户端内重试同一份不可变请求

`InferenceClient.stream` 在进入尝试循环前一次性构造 URL、headers 与 payload。每次尝试发送同一份数据；客户端不改变消息、工具或图片。配置新增 `MAX_GUI_INFERENCE_MAX_RETRIES`，默认 5，合法范围 0–5；其含义是首次请求之外的重试次数，因此默认最多 6 次网络尝试。设置为 0 可恢复当前行为。

选择客户端层是因为它能看到 HTTP 状态、响应正文、是否已经收到 SSE 增量和网络异常类型。若在 LangGraph `think` 外层重跑，会重复上下文选择、事件和流式回调，并更容易误增 ReAct 迭代。

备选方案是在 Agent 层重新进入 `think`；拒绝该方案，因为它把传输重试混同业务循环，并可能重复提交助手消息。

### 2. 只重试可恢复错误和不透明 400

默认分类如下：

- 重试：连接失败、连接/读/写/连接池超时、服务端提前断流等 `httpx` 瞬时传输异常。
- 重试：HTTP 408、425、429、500、502、503、504。
- 重试：HTTP 400 响应正文为空、无法读取、仅含通用 HTTP 客户端错误，或结构化错误明确表示模型加载中、服务繁忙、临时不可用、上游不可达/超时。
- 不重试：401、403、404、405、409、413、415、422，以及正文明确表示模型不存在、鉴权失败、上下文超限、请求字段、消息、图片、工具或 schema 非法的 400。
- 其它状态默认不重试。

分类函数返回稳定的内部原因码和安全摘要，不能只靠异常字符串散落判断。最终异常保留最后一次状态码或网络原因，并附“已重试 N 次”的中文摘要。第一次不透明 400 之后仍然发送相同请求，是为了容忍已观测到的服务抖动；若它是永久错误，最多 5 次的上限防止无限循环。

备选方案是所有 400 都重试；拒绝该方案，因为非法工具 schema 或上下文超限不会自行恢复。另一个备选方案是所有 400 都立即失败；它无法覆盖当前缺少响应正文的间歇故障。

### 3. 使用有界指数退避，并使等待可中断

第 1–5 次重试的基础等待为 0.5、1、2、4、8 秒，再加入不超过基础等待 20% 的随机抖动。服务端提供合法 `Retry-After` 时优先采用，但等待仍限制在 30 秒内。测试注入 sleep 和随机源，避免真实等待和不稳定断言。

退避等待按短间隔检查现有 `should_stop`。用户中断后不再发起新尝试，返回 `finish_reason="interrupted"`；中断不记为模型失败或重试耗尽。

### 4. 以“首个有效 SSE 增量”为重放边界

在收到正文、reasoning、工具调用片段、finish reason 或 usage 之前发生可重试错误，可以安全重放。任一有效增量已经通过回调暴露后，后续断流立即失败，不自动重放；否则正文可能在 TUI 重复，工具调用分片也可能拼成重复动作。

每个失败尝试使用新的局部 `ChatDelta` 与工具调用累加器，只有成功尝试才成为方法返回值。重试前不得调用 `on_token`/`on_reasoning`，但一旦调用过就关闭本次逻辑调用的重放资格。

备选方案是缓冲完整响应后再显示，从而允许任意时点重试；拒绝该方案，因为它会移除当前实时流式体验。服务支持 resume token 前不设计中途续传。

### 5. 一次逻辑模型调用只产生一次 started 与终态事件

`model.started` 仍代表一次 `think` 逻辑调用。客户端通过轻量 `on_retry` 回调报告 `attempt`、`max_attempts`、`reason_code`、`status_code`、`delay_ms` 和安全错误摘要；Agent 将其写为 `model.retrying` 并显示中文进度。最终 `model.completed` 或 `model.failed` 增加 `attempt_count` 与 `retry_count`。

运行汇总的 `model_calls` 仍按逻辑调用计数，不把网络尝试放大为多次模型调用；耗时包含全部尝试和退避。仅成功最终响应的 usage 进入 token 汇总。事件不得包含请求正文、图片、工具 schema、Authorization 或 API Key。

### 6. 重试不进入会话消息和检查点状态机

重试过程中不追加 user、assistant 或 tool 消息，不更新图 iteration，也不重新运行 `act`/`observe`。若后续尝试成功，按现有路径只提交一条助手消息。不可重试或耗尽后，`think` 才返回 `status="error"`，检查点保留此前已提交的工具消息，并在错误中写明最后原因与重试次数。

## Risks / Trade-offs

- [永久性不透明 400 被重复发送] → 最多 5 次、有界退避；取得明确正文后立即按永久错误停止。
- [重试延长用户等待] → TUI 实时显示次数与下一次等待；允许配置为 0；中断立即生效。
- [POST 请求通常不天然幂等] → 仅用于模型生成，且只在未输出有效增量前重放；不覆盖工具执行和其它副作用接口。
- [错误正文文案因 provider 变化导致分类漂移] → 状态码优先，结构化 `code` 优先于自由文本；未知非空 400 默认不重试并保留原始安全摘要。
- [抖动导致测试不稳定] → 注入随机源和 sleep，单元测试固定返回值。
- [流中途断开仍会失败] → 明确提示“已产生流式输出，未自动重试”；未来只有在协议支持续传或 UI 支持原子替换后再扩展。

## Migration Plan

1. 增加配置字段、默认值和 `.env.example` 说明；旧 `.env` 自动使用 5 次重试。
2. 引入错误分类、退避和重试通知值对象，再把循环接入 `InferenceClient.stream`。
3. 接入 Agent 事件与 TUI 展示，保持现有终态与会话格式向后兼容。
4. 通过模拟 transport 验证网络错误、HTTP 状态、400 正文、中断、流中途失败和最大次数。
5. 更新 README，说明“5 次重试”是首次请求之外的次数及不可重试边界。

回滚时设置 `MAX_GUI_INFERENCE_MAX_RETRIES=0` 即可关闭行为；代码回滚不需要迁移既有会话或 JSONL。

## Open Questions

无。当前设计把用户所说“最多重试 5 次”解释为首次请求失败后最多再尝试 5 次，即总网络尝试最多 6 次。
