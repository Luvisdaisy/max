## Context

当前仓库的单元、集成测试覆盖 Agent 状态机和桌面工具契约，`scripts/eval_lora.py` 仅以
ScreenAgent 的单步标注统计 JSON 格式与完全一致动作率。项目大纲第 7 周要求 20 个不同难度
桌面任务，并以任务成功率、执行时间和错误率开展系统评估。

真实 macOS 应用会受窗口布局、账号、网络和个人数据影响；而现有 `FakeDesktopBackend` 不会
随着动作演进 GUI 状态，不能测量真实浏览器中的完整闭环。因此评测需要本机、可重置的 Web
应用，同时保持 Agent 只使用现有截图和键鼠工具。

## Goals / Non-Goals

**Goals:**

- 用 Python 实现只监听 `127.0.0.1` 的 Web 测试场及其业务状态 API。
- 提供至少 20 条可重复运行的任务，覆盖基础、组合和鲁棒性 GUI 操作。
- 让 `AgentRunner` 在固定浏览器窗口中执行真实截图与键鼠操作，并由独立状态断言评分。
- 生成可审计的 JSON 和 Markdown 报告，支持基线与 LoRA 模型的同条件比较。

**Non-Goals:**

- 不向 Agent 暴露 DOM、浏览器自动化、评分接口或测试答案。
- 不操作真实文件、账号、消息服务或外部网络，也不把该测试场作为生产 Web 应用。
- 不在 CI 中驱动真实鼠标、键盘或用户桌面；真实浏览器评测由显式本地命令触发。
- 不以综合加权分替代原子指标，也不在本变更中训练或部署 LoRA 权重。

## Decisions

### 使用 Python FastAPI、Jinja2 与原生 JavaScript

测试场使用 FastAPI 提供页面、表单动作和仅供评测器访问的 API；Jinja2 和少量原生 JavaScript
实现可见界面和交互。相比 React/Vite，该选择不引入 Node 运行时或第二套构建链，并能让 Python
评测器、任务状态和 Web 服务共享类型与运行入口。

备选的纯静态页面无法可靠地重置和读取业务状态；Pillow 状态机虽然更快，但不产生真实浏览器
渲染与真实 macOS 键鼠交互，因此仅适合作为未来的低成本补充，不作为主评测。

### 任务驱动的隔离状态和独立评分

每条任务定义任务标识、页面路由、自然语言指令、初始状态、成功断言、禁止动作、工具调用上限
和超时。服务按评测运行分配状态，`POST /api/reset` 仅接收任务标识并恢复该任务初始状态，
`GET /api/state` 返回评分所需的最小业务状态。

运行器调用 API 重置及读取状态；Agent 只接收指令并通过屏幕操作页面。严格成功必须满足全部
断言；完成部分断言仅计入部分完成率。Agent 的最终文本、页面视觉相似度和截图是否已获取均不得
作为业务成功证据。

### 固定浏览器条件，复用既有 Agent 与运行日志

评测运行器在每题前将浏览器窗口尺寸、位置、缩放、语言和起始 URL 固定，再通过既有
`AgentRunner`、`ToolRegistry` 和真实桌面后端执行。执行结束、超时、达到工具调用上限、出现
Agent 错误或违反禁令都会终止本题。运行器从既有 `run.completed`、`run.failed` 或
`run.interrupted` 事件提取耗时、工具调用、工具失败和已知 Token 用量，不复制敏感正文。

这避免改动现有 Agent 或运行事件契约。浏览器启动、窗口重置和进程清理由评测命令显式负责，
不把本地 Web 服务混入 TUI 常驻运行流程。

### 20 题分层与防泄漏对比

v1 固定为 100 条任务：由 20 个不同工作流模板各生成 5 个独立任务变体；基础点击/输入/滚动、
单页业务操作、多步骤组合任务、弹窗/校验/布局变化或一次失败恢复四类各至少 25 条。每个类别均须至少覆盖一个失败或边界分支。

基线与 LoRA 对比必须使用同一任务清单、初始状态、系统提示、工具协议、迭代上限、超时和浏览器
条件；默认温度为 0。任务不得来自训练样本的同一页面轨迹；若非确定性仍存在，每题重复固定次数
并同时报告每次结果和汇总。

## Risks / Trade-offs

- [本机窗口焦点或通知干扰动作] → 评测前检查前台浏览器与固定窗口条件，失败时标记环境失败，
  不并入模型失败率。
- [评分接口被 Agent 间接访问] → 仅提供现有键鼠工具，不提供网络或浏览器开发者工具；评分 API
  只在运行器进程使用。
- [任务与训练数据或模板过近造成虚高] → 以页面工作流为单位划分保留任务，记录任务版本及来源。
- [固定坐标导致过拟合] → 同类任务采用不同内容、初始滚动位置和有限布局变体，并将成功判定绑定
  业务状态而非坐标误差。
- [真实键鼠有误操作风险] → 使用独立本地测试数据、回环地址和专用浏览器窗口；评测仅在用户显式
  启动命令时运行。
- [远程模型用量未知] → 报告将未知 Token 用量保持为 `null`，不得把未知记为零或估算为零。

## Migration Plan

1. 新增依赖、测试场和任务定义，但不改变默认 `max-gui` TUI 启动路径。
2. 先以手工浏览器操作验证所有任务重置、页面状态和成功断言。
3. 增加评测命令并以 stub 推理客户端做自动化合同测试；真实浏览器全量评测仅在本机执行。
4. 首次运行前记录浏览器与显示条件，输出的报告标记任务集版本和模型配置。
5. 若评测场出现问题，停止其独立服务并移除新增依赖即可回退；既有 Agent、桌面工具和运行日志
   不受影响。

## Open Questions

- `max --benchmark` 启动回环服务；用户在首页点击 Start 后，使用当前 `.env` 模型配置顺序运行
  全部 100 条任务。按钮是唯一允许启动真实浏览器键鼠控制的入口。
- v1 不自动保留每题最终页面截图；运行 JSONL 与报告作为默认审计证据。
- v1 每题默认运行 1 次，报告保留任务级结果，后续可按模型非确定性增加重复次数。
