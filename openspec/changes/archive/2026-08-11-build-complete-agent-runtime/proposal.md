# Why

最新 `main`（`27c46bc`）已经交付稳定的 Textual 聊天控制台、统一 `ConsoleEvent` 事件、单活动请求门禁和会话命令，但普通对话仍只支持一次只读工具解释，尚未形成能够持续规划、执行、验证、恢复并向用户追问的完整 Agent 运行时。当前编排器也不能把“找到任务栏中的记事本、切到前台、通过截图与 OCR 阅读内容、追加文字并验证结果”作为一个连续任务闭环完成。

本变更需要把编排器提升为唯一推进任务状态的核心，并将已注册工具全部纳入一个受控的模型响应—工具调用循环；同时直接复用现有聊天控制台契约，不重新设计或修改控制台界面。这样 `max-agent` 默认启动后即可通过普通对话执行较复杂的 Windows 桌面任务，无需显式传入 `--enable-desktop-control`。

# What Changes

- 建立完整的 `AgentRuntime` 生命周期，以“模型返回最终文本则结束、模型返回一个结构化工具调用则执行并把净化结果加入任务消息上下文”的受控 ReAct 循环推进任务，并对模型轮次、工具调用、动作、重试、超时与重复行为设置硬限制。
- 让 `tools/registry.py` 继续作为编排器调用感知、模型、安全、桌面执行、验证、恢复和归档能力的唯一入口，并为所有已注册工具提供统一 schema、调用结果和运行事件。
- 将内存截图和 OCR 作为主要视觉读取链路：截图不落盘即可进入 OCR，返回带坐标和置信度的结构化文本；UIA 仅用于明确需要控件语义或 OCR 无法可靠定位的场景。
- 引入严格的模型响应协议：每轮只能返回面向用户的最终文本，或一个引用注册表白名单的结构化工具调用；不解析自由文本中的 Thought/Action 标签，也不保存模型原始思维链。
- 修复当前普通消息几乎都会先调用一次 `observe_screen` 并夹带屏幕理解的问题：首轮模型调用只接收系统提示、对话历史和用户消息；普通问答可直接返回最终文本，只有模型明确调用感知工具时才执行截图/OCR。
- 对只读工具执行名称、参数、阶段和预算校验；对窗口激活、点击、键盘和文字输入等有副作用工具额外强制经过 Guard，并在执行后自动重新观察和验证，再把净化工具结果交回模型继续下一轮。
- 为窗口激活、鼠标、键盘和文字输入建立默认启用的安全执行边界，包括目标绑定、坐标新鲜度、危险动作确认、物理输入互斥、紧急停止和审计归档。
- 在动作后强制重新观察并验证状态变化；失败时使用有限恢复预算重新定位、重新规划或向用户请求帮助，禁止无限循环。
- 将普通聊天消息接入 `AgentRuntime`，把运行阶段和工具进度映射到现有 `ConsoleEvent`；保留当前 Textual 布局、事件渲染、单活动请求和命令体验，不修改 `ChatConsoleApp`、`console_frontends.py`、`console_core.py` 或 `local_llm.py`。
- 为对话式长任务增加可恢复的 `WAITING_USER` 状态：运行时释放桌面控制锁后返回问题，下一条普通消息继续同一任务；`/clear` 与 `/model` 按明确规则清除或失效挂起任务。
- 以记事本端到端场景验证完整闭环：识别任务栏或现有窗口中的记事本、激活窗口、截图、OCR 读取已有内容、在末尾追加用户指定文本、再次截图并验证结果。

# Capabilities

## New Capabilities

- `agent-runtime-lifecycle`: 定义完整 Agent 消息循环、任务生命周期、运行状态、预算、事件、取消、等待用户和终止语义。
- `model-action-planning`: 定义模型每轮可返回的最终文本或单个结构化工具调用、上下文裁剪、格式校验和终止规则。
- `desktop-action-control`: 定义默认启用但受安全策略约束的窗口、鼠标、键盘和文字输入动作。
- `desktop-result-verification`: 定义动作后的重新观察、结果验证、有限恢复与记事本端到端验收。

## Modified Capabilities

- `agent-orchestration`: 将现有固定“观察—规划—审批—执行—验证—恢复”链路扩展为模型响应驱动、程序白名单路由的受控 ReAct 循环，并统一调度全部工具。
- `perception-tools`: 在现有截图工具基础上增加内存图像交接、OCR 文本识别和坐标化观察结果，明确 OCR 优先、UIA 按需的策略。
- `chat-console-ui`: 将普通聊天请求从一次只读工具解释切换为完整 `AgentRuntime`，同时保持现有 Textual 界面与事件契约，并补充挂起任务、模型切换、清空会话和真实安全边界状态的行为。

# Impact

- 基线固定为已合入 `main` 的 `27c46bc`；不再依赖并行控制台分支，也不需要后续 rebase 协调。
- 主要影响 `src/max_agent/orchestrator.py`、`src/max_agent/tools/`、新增的运行时/规划/验证模块、配置与测试；聊天侧仅允许在 `src/max_agent/cli.py` 及相关测试中增加适配，不重构控制台实现。
- `max-agent` 的默认普通消息行为将从“本地模型 + 最多一次只读工具”升级为有限多轮的模型响应—工具调用循环；斜杠命令、单活动请求、事件渲染和模型选择体验保持兼容。
- 默认具备桌面操作能力，但每个有副作用的动作仍必须通过策略检查、目标绑定、互斥和审计；默认启用不等于绕过确认或安全边界。
- 不新增第三方直接依赖，优先复用现有截图、OCR、Windows API 和模型运行能力；模型文件仍仅存放于 `model/`，诊断和运行证据仍仅存放于 `artifacts/`。
- 公开命令、模块职责、安全边界和已实现能力发生变化时，实施阶段必须同步更新 `tech-design.md`、必要的 `README.md` 和自动化测试。
