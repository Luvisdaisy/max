## Why

当前 TUI 只能在本进程内显示粗粒度状态，会话 JSON 也要到图结束后才可靠反映终态，无法在运行中回答任务属于哪次执行、当前模型或工具调用耗时多久、崩溃发生在哪一步。需要为本机单用户开发排障增加独立、可持久化的运行事件轨迹，同时保留现有会话恢复能力。

## What Changes

- 为每次用户提交建立独立 `run_id`，中断恢复沿用原运行并记录恢复事件。
- 定义带版本、顺序号、时间、会话、轮次、子任务和数据载荷的结构化运行事件。
- 在 `AgentRunner` 的运行、状态迁移、模型调用、工具调用与观察阶段发出事件。
- 将每次运行追加写入独立 `artifacts/runs/<run-id>.jsonl`，默认无限保留，不自动轮转或清理。
- 保持 reasoning 与现有截断规则下的工具参数在会话 JSON 中持久化；运行事件通过消息位置引用这些内容，避免重复保存 reasoning 和键盘输入正文。
- 在 TUI 中默认打开独立运行监控面板，显示当前状态、轮次、子任务、活动调用、累计耗时、统计摘要与最近事件，不污染会话记录区。
- 运行日志仅面向本机开发排障；不增加远程接口、集中日志、Prometheus、OpenTelemetry Collector、防篡改审计或多进程聚合。
- **BREAKING**：撤销 `session-store` 现有“不得另写 `artifacts/runs/` 执行日志”的要求，改为会话快照与运行事件日志并存。

## Capabilities

### New Capabilities

- `run-observability`: 定义本地运行身份、结构化事件、JSONL 持久化、恢复关联、无限保留和故障降级行为。

### Modified Capabilities

- `react-agent`: 为 Agent 执行增加运行上下文，并在状态机、模型、工具和观察边界发出运行事件。
- `session-store`: 允许独立运行日志，通过会话消息位置关联 reasoning 与现有工具参数，并保留现有会话持久化职责。
- `tui-repl`: 默认展示独立的本地运行监控面板，实时消费事件摘要且不混入会话记录。

## Impact

- `src/max_gui/agent/`：运行上下文、事件产生时机、恢复语义与汇总统计。
- `src/max_gui/session/`：会话与运行之间的引用、原有持久化边界调整。
- 新增本地运行事件模型、发布器与 JSONL 存储实现，产物写入 `artifacts/runs/`。
- `src/max_gui/app.py`：独立监控面板、默认显示及事件订阅。
- `tests/`：事件顺序、增量写入、中断恢复、故障降级、敏感内容不重复写入和 TUI 实时展示测试。
- `README.md`：说明运行日志无限保留，且会话、截图和工具参数可能包含敏感信息。
- 不要求新增第三方运行时依赖，也不增加网络监听端口。
