## Why

当前 Textual 对话界面仅以无差别文本追加用户消息、模型回复、命令结果和错误，且缺少多行输入、命令发现和可靠的单任务运行反馈，难以支撑面向开发任务的长时间交互。需要将其提升为键盘优先、状态透明的本地终端 Agent 工作台，同时保持现有离线运行与只读工具安全边界。

## What Changes

- 重构 Textual 会话布局，以明确区分用户、MAX、系统、命令结果、工具状态与错误，并使用一致的终端主题、留白和响应式布局。
- 使用 Markdown 渲染模型最终回复，使标题、列表、代码块和行内代码适合开发任务阅读。
- 将单行输入升级为支持换行的键盘优先编辑区，定义发送、换行、命令历史和焦点恢复行为。
- 在输入 `/` 时提供可筛选的斜杠命令菜单，并新增会话内 `/help`、`/clear` 和 `/status` 命令；保留 `/model`、`/doctor` 与 `/quit`。
- 将会话展示结果改为最小化的结构化事件，使前端能够呈现角色、运行阶段和结果类别，而无需解析展示字符串。
- 在本地推理期间强制单活动请求，锁定重复提交并显示加载阶段与耗时，完成或失败后可靠恢复输入。
- 显示经过净化的工具执行摘要（工具名、状态与耗时），不显示或持久化原始截图及工具原始数据。
- 将工具选择、参数校验和只读工具执行失败作为受控观察交回模型，使 Agent 在不重试工具的前提下理解失败并继续回答原始消息；仅最终回复生成失败才中断本轮对话。
- 增加窄终端、中文宽字符、自动滚动、用户回看历史和错误恢复等可用性行为及对应自动化测试。
- 本变更不新增桌面执行、文件修改、网络访问、会话持久化、完整权限系统或 Plan/执行模式。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `chat-console-ui`: 扩展现有 Textual 聊天契约，定义终端会话的信息层级、多行输入、命令发现、单活动请求状态、净化工具摘要和响应式可用性行为。

## Impact

- 主要影响 `src/max_agent/console_frontends.py`、`src/max_agent/console_core.py`、`src/max_agent/cli.py` 以及只读工具解释流程的错误观察与会话事件衔接。
- 需要扩展 Textual 前端测试、命令分发测试和运行状态测试；不引入新的第三方依赖。
- `max-agent` 与 `max-agent --chat` 的公开启动方式保持不变，现有 `/model`、`/doctor`、`/quit` 语义保持兼容。
- 需要同步更新 `README.md` 与 `tech-design.md` 中的已实现交互行为。
