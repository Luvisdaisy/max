# agent-task-evaluation Specification

## Purpose

通过本地、可审计且可重置的 GUI 任务集评估 Agent，报告基础模型与 LoRA 模型在一致实验条件下的原子指标与逐题证据。

## Requirements

### Requirement: 显式启动的全量自动评测

系统 SHALL 提供 `max --benchmark` 入口，启动仅绑定回环地址的评测首页。首页 MUST 显示 Start
按钮；只有用户点击该按钮后，系统才可使用当前 `.env` 模型配置启动浏览器并顺序执行完整 100 条
任务。页面 MUST 显示总进度、当前任务和终态报告路径。

#### Scenario: 点击 Start 后运行全量任务集

- **WHEN** 用户以 `max --benchmark` 启动评测首页并点击 Start
- **THEN** 系统重置并依次执行 100 条任务，页面显示进度，全部结束后写入报告

### Requirement: 版本化任务定义

系统 SHALL 从版本化任务定义加载不少于 100 条 GUI 评测任务。每条任务 MUST 包含唯一标识、
页面路由、自然语言指令、初始状态、成功断言、禁止动作、工具调用上限、超时和难度或类别标签。

#### Scenario: 加载完整 v1 任务集

- **WHEN** 评测运行器加载 v1 任务集
- **THEN** 任务集含至少 100 条任务，并覆盖基础操作、单页操作、多步骤组合和鲁棒性四类任务

### Requirement: 独立状态断言评分

评测运行器 SHALL 在每题终止后读取测试场业务状态并逐项检查成功断言。全部断言满足时 MUST
记为严格成功；仅部分满足时 MUST 报告通过断言数和部分完成率，且 MUST NOT 计入严格成功率。
Agent 的最终文本不得单独构成任务成功。

#### Scenario: 部分完成不计严格成功

- **WHEN** 创建项目和待办成功，但待办优先级未达到任务要求
- **THEN** 结果记录已通过和总断言数，严格成功为否，任务不计入成功率分子

### Requirement: 明确任务终止条件

评测运行器 MUST 在 Agent 到达终态、超过任务超时、超过工具调用上限或触发禁止动作时终止当前题。
超时、上限、Agent 错误、中断和违规 MUST 在结果中使用可区分的终止原因；环境准备失败 MUST 单独
报告，且 MUST NOT 计入模型任务失败率。

#### Scenario: 工具调用超过上限

- **WHEN** 一条任务的工具调用次数超过其定义上限
- **THEN** 运行器停止该任务，结果终止原因为工具调用上限，严格成功为否

### Requirement: 可审计原子指标报告

评测运行器 SHALL 为每个任务输出 JSON 结果，并为整次评测输出 JSON 和 Markdown 汇总。结果
MUST 包含任务标识、任务集版本、模型标识、严格成功、断言进度、终止原因、执行时间、工具调用数、
工具失败数、无效动作数、违规记录和已知 Token 用量；未知 Token 用量 MUST 保留为 `null`。汇总
MUST 分别报告任务成功率、部分完成率、平均执行时间、平均工具调用数、工具失败率、无效动作率、
违规率和已知 Token 用量，MUST NOT 以不透明综合分替代这些指标。

#### Scenario: 已知与未知 Token 用量并存

- **WHEN** 一次评测中部分运行日志含 Token 用量、部分运行日志不含该字段
- **THEN** 单题未知值为 `null`，汇总只基于已知值报告 Token 用量，并标明已知样本数

### Requirement: 模型对比保持实验条件一致

系统 SHALL 支持在同一任务集上分别运行基础模型与 LoRA 模型。对比运行 MUST 使用相同任务定义、
初始状态、浏览器条件、系统提示、工具协议、迭代上限、超时和温度；报告 MUST 记录模型配置与每题
结果，便于复核。

#### Scenario: 生成基础模型与 LoRA 对比报告

- **WHEN** 使用同一任务集运行基础模型和 LoRA 模型
- **THEN** 报告分别给出两者的原子指标和每题结果，并标注一致的任务集版本及执行限制
