## Context

`Session` 已持久化完整消息、截图路径、`ViewFrame` 与定位命中，但 `AgentRunner` 每次新用户输入都会创建独立 `TaskContext`，上下文选择器只发送当前任务用户消息和当前任务工具链。此前会话中的截图不会进入“你看到了什么？”这类追问；同时，恢复的 `ViewFrame` 和 `locate_hits` 若被新任务误用，会把历史桌面状态当作当前可执行状态。

真实 Dock 截图还表明，现有 `locate` 的 YOLO 检测能返回图标框，却可能因 OCR / caption 回退而让全部标签成为 `icon`。`grounded_facts` 只保留六项，按空间顺序截断时又会丢失 Dock 候选。现有安全闭环——当前帧 `target_id`、`mouse_move` 后置截图、无坐标点击——必须保持不变。

## Goals / Non-Goals

**Goals:**

- 让连续追问能读取有限、脱敏、只读的历史视觉观察。
- 在新桌面任务开始时失效旧执行帧与定位编号，避免历史观察变成输入授权。
- 为命名 Dock 应用和通用图形控件提供可检验的语义候选，减少模型从无名框猜坐标。
- 在 macOS 上优先利用辅助功能标题和边界作为观察信息，但仍以既有鼠标与截图链路实际操作。

**Non-Goals:**

- 不实现长期记忆、向量检索、跨会话知识库或保存完整 OCR / caption 正文。
- 不允许辅助功能 API 直接执行应用、点击 Dock，亦不绕过鼠标移动与后置截图核验。
- 不保证每个第三方应用都暴露辅助功能元素；缺权限或不支持时不得伪造成功。
- 不扩大为跨平台完整无障碍树自动化；首版仅解决 macOS Dock 的命名应用发现与通用视觉回退。

## Decisions

### 1. 会话级历史观察与任务级执行状态分离

在 `Session` 新增可选 `conversation_context`，只保存最近有限的文本摘要和一张存在的历史观察图路径、时间与来源。它不包含 `target_id`、逻辑坐标、OCR 全文、键入正文或工具原始 JSON。旧会话缺字段时视为空。

新用户回合先将上一回合的可读观察同步到会话级上下文；若本回合没有用户附件和当前任务新观察，模型可得到该图并获知其“仅用于回答/理解”。与此同时，开始一个新桌面任务前必须清空活动 `ViewFrame`、`locate_hits` 与当前任务的可执行事实。这样“看图回答”可使用旧图，而“点击它”必须重新截图。

备选方案是继续把每条输入彻底隔离；它安全但无法支持自然追问。另一方案是跨任务保留 `ViewFrame` 与编号；因桌面可在用户回合间变化，被拒绝。

### 2. 单图编码采用明确优先级

维持主推理一次最多发送一张内联图，优先级为：本轮用户附件、当前任务最新观察、会话级最近历史观察。历史图仅在前两者均不存在且文件仍存在时进入请求。上下文预算对最终选择的唯一图预留 token，并将其来源记为不含路径正文的诊断类别。

选择单图而不是增加图数，是为了适配当前小模型和实际 4K 上下文风险；“描述上一张图”并不需要把当前图与旧图同时发送。需要前后比较的未来能力另行提案。

### 3. 语义定位先收敛候选，再授予编号

扩展 `locate` 以接受可选 `query` 与限定区域（首版支持 Dock）。无查询的行为仍返回通用框，但不把重复的泛化标签写入有限事实。带查询时，工具先检测区域中的候选，再用 OCR、可用的 icon caption 与别名匹配收敛结果；仅当存在唯一、可信匹配时，才为该项写入当前帧 `target_id` 并把“Chrome”等语义标签纳入 `grounded_facts`。

caption 初始化、模型文件缺失、推理异常和无语义匹配都必须以机器可读状态和中文摘要返回。不得以 `icon`、空标签或多个同名候选冒充匹配。备选方案是扩大事实条数并把 40 个框都喂给模型；这只增加 token，无法消除名称歧义。

### 4. macOS Dock 使用只读辅助功能优先发现

新增只读 `find_dock_app(name)`，仅在 macOS 上读取 Dock 无障碍树中的标题、角色与屏幕边界，按规范化名称 / 已知别名匹配一个应用。返回值转换为当前帧视图中的候选，并复用 `mouse_move(target_id=...)` 与截图核验；不调用 AXPress 或任何直接动作 API。

调用前检查辅助功能信任状态。无权限、Dock 未暴露元素、元素不在当前活动截图内或候选不唯一时，返回可诊断的未匹配状态，模型可改用带查询的视觉 `locate` 或询问用户。选择窄化 Dock API 而非通用全屏无障碍树，是因为当前问题是命名 Dock 应用，且可控制跨应用兼容性与权限风险。

## Risks / Trade-offs

- [历史图被误当当前界面] → 新桌面任务清空执行帧；模型提示与工具门禁均要求动作前重新截图。
- [会话上下文增长或泄露敏感内容] → 一图、短摘要、固定上限；不保存 OCR、caption、坐标、键入正文或 base64。
- [Dock 辅助功能权限缺失或版本差异] → 显式权限 / 不支持码并回退视觉定位，不直接执行动作。
- [caption 加载慢或静默退化] → 记录初始化与调用状态；查询模式只处理限定区域候选，未就绪时快速返回未匹配。
- [同名应用或视觉误识别] → 只有唯一可信匹配才提供可执行编号；多候选时不得移动鼠标。
- [新语义工具放松安全边界] → 编号仍只绑定活动 `ViewFrame`，移动后旧编号失效，点击仍需红十字后置截图。

## Migration Plan

1. 为 Session / checkpoint 增加可选会话级历史观察字段，并保持旧 JSON 可读。
2. 在新回合初始化、上下文选择和图像编码中接入只读观察，先覆盖“描述上一张截图”和“新动作必须重截图”测试。
3. 为 `locate(query, region)` 增加语义结果与 caption 诊断，保留无参数调用兼容性。
4. 在 macOS 增加只读 Dock 辅助功能适配层与权限错误处理，再连接到现有移动 / 核验链。
5. 通过 fake desktop、mock accessibility、固定截图和真实 macOS 冒烟分别验证；回滚时忽略新会话字段、关闭语义发现，并让 `locate` 保持原有通用框行为。

## Open Questions

- `find_dock_app` 应作为公开模型工具，还是由 `locate(query, region="dock")` 在 macOS 内部优先调用？首选后者以减少 schema 数量，但实现时需确认可观测性需求。
- 应支持哪些中英文应用别名，以及是否允许用户配置？首版仅接受精确标题和少量内置浏览器别名。
- 历史观察摘要应保留几条纯文本消息？首版建议最多两条且不复制 reasoning。
