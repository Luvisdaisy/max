## Context

当前仓库只有 `diagnostics.py` 对 mss、OpenCV、PaddleOCR、pynput 的就绪检查；`src/max_agent/tools/` 尚不存在。`tech-design.md` 已指定未来感知实现的位置和五类工具。详见 `proposal.md` 与 `specs/perception-tools/spec.md`。

## Goals / Non-Goals

**Goals:**

- 以小型 Pydantic 数据契约统一工具输入、结果与可恢复失败回执。
- 让 `tools/registry.py` 成为未来编排器调用感知工具的唯一入口。
- 把真实 OS/第三方库调用收敛在各自的感知模块中，并使合成图像和 mock 后端可单元测试。

**Non-Goals:**

- 不实现 Agent 编排器、模型调用、动作审批、桌面输入、验证或归档工具。
- 不新增除 Doctor 之外的 CLI 命令，也不做真实业务窗口的端到端测试。
- 不下载 PaddleOCR 模型，不将截图、OCR 文字或标注图写入磁盘。

## Decisions

### 单一工具契约和注册表

定义最小 `Tool` Protocol、`ToolReceipt` 与标准失败码；注册表保存工具名到实现的映射并负责输入校验和异常边界。选择这一方案而非让调用者直接导入各模块，因为后续编排器需要单一的能力发现、调用和审计边界。不会在此阶段实现编排器或插件生命周期。

### 输入图像全程驻留内存

截图输出和 OCR、视觉、SoM 的输入均使用 PIL/NumPy 内存对象，结果携带像素坐标和显示器元数据。选择内存对象而非路径引用，避免默认将可能敏感的桌面内容持久化；归档需求将在后续独立、经授权的归档工具中处理。

### 每种外部依赖保留窄适配层

`screen.py` 只适配 mss，`ocr.py` 只适配 PaddleOCR，`uia.py` 只适配 pywinauto，`vision.py` 和 `som.py` 只适配 OpenCV/Pillow。依赖在工具首次调用时导入，避免普通导入触发 GUI 访问或 OCR 初始化；OCR 初始化设置为本地资源模式，异常转为失败回执。相比共享“大型感知服务”，这种布局更容易 mock，并防止工具间隐式串联。

### 明确的只读安全边界

UIA 工具仅连接并读取目标窗口，不调用激活、聚焦、点击、输入或修改属性的 API。截图和图像工具只处理其输入。所有实现通过测试确保不调用 PyAutoGUI、pynput 或 UIA 写操作；这比依赖调用方遵守约定更可审计。

### 坐标保持物理像素

截图、OCR、匹配和 SoM 均以图像原点为基准返回像素坐标；屏幕截图另附显示器边界与 DPI 元数据。选择不在感知层归一化坐标，避免多显示器和缩放下丢失精度；未来执行/安全层可基于这些元数据完成转换和校验。

### 恢复受限的 Doctor CLI

在现有 CLI 参数解析中恢复 `doctor` 子命令，接受 `--artifact-root` 与显式 `--desktop-probe`。默认调用保持无输入；只有用户传入 `--desktop-probe` 时才将该标志传入既有诊断实现。选择复用 `_doctor_operation` 而非复制诊断路径，确保 CLI 与 `/doctor` 共用同一归档和结果格式。

### 使用 Win32 原生控件作为桌面探针夹具

`--desktop-probe` 使用 `ctypes` 创建进程内 Win32 顶层窗口、`Edit` 与自动复选 `Button` 控件，并运行受限消息循环；不再使用 Tk。探针仅在顶层句柄成为前台窗口且目标控件坐标通过命中测试后发送输入，键盘注入检查 `SendInput` 返回数量并从原生 `Edit` 读取文本，鼠标点击通过按钮选中状态确认。选择原生控件是因为 Tk 8.6.2.15 在当前 Windows 环境中未接收已发送的合成键盘事件，且直接干预焦点曾触发 `tk86t.dll` 原生崩溃；继续以 Tk 作为夹具无法代表 Agent 控制外部 Win32 应用的目标能力。原生夹具仍在短生命周期子进程中运行，使超时或原生异常不会中断父 Doctor。

## Risks / Trade-offs

- [无头或锁屏会话无法截图或连接 UIA] → 转化为明确失败回执，并在测试中使用合成图像和 mock。
- [PaddleOCR 首次初始化会很慢或本地资源不完整] → 仅按需初始化、禁止下载并将初始化错误返回给调用方。
- [UIA 元素树过大或受进程完整性级别限制] → 限制观察范围与遍历数量，并返回部分/失败的结构化状态；不尝试提升权限。
- [图像对象使回执占用内存] → 仅传递当前调用所需的图像，不做全局缓存；调用方负责在消费后释放引用。
- [Win32 探针在锁屏、非交互会话或被更高完整性窗口遮挡时无法获得前台] → 在任何输入前标记为跳过或失败；不提升权限，也不回退到真实业务应用。

## Migration Plan

1. 添加工具契约、注册表和五个感知模块及单元测试。
2. 使用合成图像、假截图源、假 OCR/UIA 适配器验证结构化结果和失败边界。
3. 运行完整单元测试、`pip check` 与无输入 Doctor；在授权的交互式 Windows 会话中人工复核截图和只读 UIA 观察。
4. 验证 `max-agent doctor --artifact-root artifacts` 默认不发送输入，并仅在交互式 Windows 会话中使用 Win32 原生夹具验证 `--desktop-probe`。
5. 若需回退，移除注册表中的感知工具注册，并恢复仅支持聊天会话的 CLI 解析；本变更不迁移数据。
