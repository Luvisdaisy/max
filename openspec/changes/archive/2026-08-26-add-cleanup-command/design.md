## Context

记录由三个相互独立的目录产生：会话文件使用配置中的 `sessions_dir`，截图使用配置中的 `screenshots_dir`，运行事件由 `RunRecorder` 写入项目根下的 `artifacts/runs/`。当前 CLI 只负责启动 TUI、服务或评测，没有统一的记录清理入口。

## Goals / Non-Goals

**Goals:**

- 在现有 argparse 子命令体系中增加 `cleanup`。
- 只清理明确的三个记录目录，并保留目录本身。
- 命令直接执行清理，不读取交互输入，也不保留确认参数。
- 将递归删除逻辑放在可单测的独立函数中，并返回每个目录的删除数量。

**Non-Goals:**

- 不清理模型权重、`.env`、其他 `artifacts` 内容或用户工作区文件。
- 不增加自动轮转、按时间筛选或恢复机制。
- 不在清理命令中校验推理服务、API Key 或模型权重。

## Decisions

- **清理目标使用项目根下的固定记录目录**：复用 `Settings.project_root`、`Settings.sessions_dir` 与 `Settings.screenshots_dir`，运行目录固定为 `project_root/artifacts/runs`。这样与现有写入路径一致，也避免 `--workspace` 把清理范围扩大到任意用户目录。
- **删除目录内容而不是目录本身**：对每个目标目录递归删除文件与子目录，再确保目标目录存在。保留目录可避免下次记录写入出现目录缺失，也让结果稳定可预测。
- **直接执行且不保留兼容参数**：`cleanup` 启动后直接清理三个固定目录，不读取标准输入，也不提供 `--yes` 等确认或兼容参数。调用方通过显式选择 `cleanup` 子命令表达删除意图。
- **删除失败即报告并返回非零**：逐个目标目录执行，继续尝试其他目标，汇总成功与失败；只要存在失败就退出码为 1。路径遍历和符号链接不作为目标目录外的删除入口，目录本身解析后必须位于项目根内。

## Risks / Trade-offs

- [Risk] 删除不可恢复 → 命令名明确表达破坏性操作，输出清理结果，并限制在三个固定记录目录内。
- [Risk] 运行中的 Agent 仍持有记录文件 → 该命令不强制终止运行；并发写入可能导致单个文件删除失败，失败会被报告且以非零状态退出。
- [Risk] 目录中出现非标准文件 → 递归清理会删除目标记录目录中的全部内容，这是“清除所有记录”的定义；目标目录外不受影响。
