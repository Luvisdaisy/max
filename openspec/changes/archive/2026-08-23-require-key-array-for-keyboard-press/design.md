## Context

现有 schema 同时声明字符串与字符串数组，解析器也接受两种形式。历史会话表明模型会把数组示例再编码为字符串，产生无法识别的伪键名。底层 `hotkey` 已以可变参数接收键列表，无需改变后端。

## Goals / Non-Goals

**Goals:**

- 为单键和组合键提供唯一、可机器校验的调用格式。
- 在调用后端前拒绝所有非数组、空数组、非字符串元素及未知键名。
- 保持既有键白名单、安全拦截和截图前置条件。

**Non-Goals:**

- 不扩大可用键集合，不改变 PyAutoGUI 行为。
- 不兼容历史字符串调用，也不尝试解析数组文本字符串。

## Decisions

- `keys` 的 schema 使用 `array`，并设置 `minItems: 1`；工具描述仅展示 JSON 数组。这样模型的函数调用约束与示例一致。
- `_parse_keys` 仅接受 `list`，逐项验证为 `str`，再进行别名规范化和既有安全检查。错误消息明确要求 `keys` 为字符串数组，便于模型在下一轮纠正。
- 单键也必须传单元素数组，如 `["enter"]`。统一格式避免字符串和数组的分支再次漂移。

## Risks / Trade-offs

- [已有调用方传字符串将失败] → 这是用户要求的破坏性收紧；错误消息给出唯一格式。
- [模型仍然输出数组文本字符串] → 工具立即拒绝且返回正确 JSON 示例，避免把无效动作伪装为成功。
