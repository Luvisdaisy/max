# agent-runtime-lifecycle Specification

## Purpose

为本地桌面任务提供唯一、完整、可恢复且可审计的 Agent Runtime 生命周期，使任务从接收目标到对话答复、等待用户、恢复执行和终态清理都由同一个受预算约束的运行时推进。

## Requirements

### Requirement: 默认启动可执行的 Agent Runtime
系统 SHALL 在 `max-agent` 的普通任务入口默认创建具备桌面控制能力的 Agent Runtime，且 MUST NOT 要求用户传入 `--enable-desktop-control` 或等价的正向启用参数。默认能力 MUST 始终受动作审批、会话锁、Fail-safe、预算和高影响确认策略约束。

#### Scenario: 默认处理桌面任务
- **WHEN** 用户通过 `max-agent` 提交一个需要观察和操作桌面的普通目标
- **THEN** 系统启动 Agent Runtime 并在无需额外启用参数的情况下进入受控观察与行动循环

#### Scenario: 默认能力不绕过安全策略
- **WHEN** Agent Runtime 默认具备桌面控制能力
- **THEN** 每个产生桌面输入的动作仍须经过审批并满足当前窗口、策略、预算和 Fail-safe 条件

### Requirement: 单任务生命周期与独占桌面控制
系统 SHALL 为每个目标创建唯一任务状态，并以显式阶段推进模型响应、工具校验、会话获取、执行、动作后观察、验证、恢复、用户等待和终态处理。同一交互式桌面会话在任一时刻 MUST 只允许一个运行中的任务持有桌面控制锁；第二个运行中任务 MUST 在发送任何输入前返回可机器处理的忙碌结果。

#### Scenario: 获取空闲桌面会话
- **WHEN** 没有其他任务持有桌面控制锁且新目标开始
- **THEN** 运行时获取独占桌面控制权并开始观察，不允许工具自行创建第二个任务循环

#### Scenario: 拒绝并发控制
- **WHEN** 一个任务已持有桌面控制锁且另一个任务请求运行
- **THEN** 第二个任务以 `SESSION_BUSY` 结束或等待调用方重试，且不观察敏感内容、不发送输入也不抢占现有任务

### Requirement: 统一预算、取消和超时
运行时 SHALL 统一管理最大模型轮次、工具调用次数、动作步数、格式纠正次数、恢复次数、单步超时和任务总超时，并 MUST 在每次模型调用、工具调用或桌面输入前检查剩余预算。调用方取消、Fail-safe、任一硬预算耗尽或超时 MUST 阻止对应后续调用并进入人工等待或可审计终态。

#### Scenario: 动作预算耗尽
- **WHEN** 任务已达到允许的最大动作步数且尚未验证成功
- **THEN** 运行时以 `FAILED` 和 `STEP_BUDGET_EXHAUSTED` 终止，不再调用规划或执行工具

#### Scenario: 用户取消正在运行的任务
- **WHEN** 调用方在任一非终态请求取消
- **THEN** 运行时转为 `ABORTED`，停止后续工具调度并执行输入状态清理

#### Scenario: 单步超时
- **WHEN** 任一工具调用超过当前单步时间预算
- **THEN** 运行时记录 `TIMEOUT`，停止后续桌面输入并进入清理和终态归档

#### Scenario: 模型轮次耗尽
- **WHEN** 模型持续返回工具调用且已达到最大模型轮次
- **THEN** 运行时不再请求模型或执行新工具，并以 `MODEL_TURN_BUDGET_EXHAUSTED` 终止

### Requirement: 对话式任务结果与用户等待恢复
运行时 SHALL 为每次普通消息维护由系统提示、对话消息、模型工具调用和工具结果构成的任务级消息上下文，并返回包含任务状态、面向用户的 `response_text`、脱敏结果摘要和可选恢复标识的结构化结果。模型返回可接受的最终文本时运行时 MAY 直接以 `SUCCEEDED` 返回；工具或策略需要用户补充、授权或人工处理时 MUST 以 `WAITING_USER` 返回明确问题，并保存最小化的可恢复任务状态。处于 `WAITING_USER` 的任务 MUST 释放桌面控制锁、所有按键或鼠标输入状态、截图对象和完整 OCR 文本；下一条普通消息 SHALL 作为同一任务的用户消息恢复循环，任何新桌面动作前 MUST 重新获取桌面控制锁与新观察，并使旧坐标、旧审批和旧窗口绑定失效。

#### Scenario: 普通问候直接完成
- **WHEN** 用户消息不需要桌面观察或工具调用且模型返回最终文本
- **THEN** 运行时返回 `SUCCEEDED` 和可直接展示的 `response_text`，不获取桌面控制锁也不调用桌面工具

#### Scenario: 信息不足时等待用户
- **WHEN** 模型调用请求用户补充信息的受控工具，或 Guard 要求用户授权
- **THEN** 运行时清理桌面输入、释放桌面控制锁，以 `WAITING_USER` 返回明确问题并保存脱敏的最小恢复状态

#### Scenario: 下一条消息恢复挂起任务
- **WHEN** 同一交互会话存在一个 `WAITING_USER` 任务且用户提交下一条普通消息
- **THEN** 运行时将消息合并为该任务的新信息，重新获取锁并重新观察桌面后继续规划，不复用等待前的坐标、审批或窗口新鲜度

#### Scenario: 挂起任务恢复时桌面已变化
- **WHEN** 恢复前的新观察表明目标窗口或显示拓扑已不同于等待前状态
- **THEN** 运行时基于新观察重新规划或再次请求用户处理，不执行等待前候选动作

### Requirement: 按需获取桌面观察
运行时 SHALL 在创建任务后先把系统提示、对话历史和用户消息交给模型，不主动获取桌面观察。只有当模型返回合法感知工具调用时，运行时 MAY 执行截图、OCR、UIA 或窗口观察并把净化结果作为工具消息回填。运行时 MUST NOT 为普通问候、知识问答、命令帮助或其他模型可直接以最终文本回答的消息自动调用 `observe_screen`、OCR、UIA 或窗口枚举，也不得在答复中附加未被用户请求的屏幕理解。

#### Scenario: 普通问题不观察屏幕
- **WHEN** 用户问题可仅依据对话生成最终文本
- **THEN** 运行时直接返回答复，且桌面观察工具调用数为零、桌面控制锁从未被获取

#### Scenario: 桌面目标按需开始观察
- **WHEN** 模型返回一个需要当前桌面证据的合法感知工具调用
- **THEN** 运行时检查名称、参数、阶段和预算，随后调用获准的观察工具并将净化结果加入下一轮模型消息

#### Scenario: 模型为普通问题错误请求观察
- **WHEN** 模型为明显无需桌面上下文的普通问题返回不适用或当前未授权的桌面观察工具调用
- **THEN** 运行时拒绝该调用并把安全错误结果加入消息上下文，不截图也不向最终答复注入屏幕理解

### Requirement: 终态清理与脱敏归档
任务进入成功、失败或中止终态时，运行时 MUST 释放按键、鼠标按键、任务内存资源和桌面控制锁，并 SHALL 写入包含结果、耗时、步数、失败码、工具回执摘要和验证证据的脱敏归档。原始截图、完整 OCR 文本、输入文本、密码和剪贴板内容 MUST NOT 默认写入归档。

#### Scenario: 成功任务结束
- **WHEN** 验证工具确认用户目标完成
- **THEN** 运行时先完成输入清理和锁释放，再返回 `SUCCEEDED`、面向用户的答复及脱敏验证证据

#### Scenario: 清理期间发生异常
- **WHEN** 任务终止后的输入状态释放或资源清理失败
- **THEN** 系统记录独立高优先级清理错误、继续尝试释放剩余资源，并且不得恢复任务执行

### Requirement: 前端无关的运行事件与结果
运行时 SHALL 向调用方提供前端无关的结构化循环事件和最终结果。展示事件 MUST 仅包含允许的模型轮次阶段、工具名、状态、耗时和脱敏说明，不得携带截图、工具参数、原始回执、输入文本或模型思维过程；最终结果 MUST 包含可展示的 `response_text`，并用确定状态区分 `SUCCEEDED`、`WAITING_USER`、`FAILED` 与 `ABORTED`。调用方不提供事件接收器时，运行语义 MUST 保持一致。

#### Scenario: 调用方接收阶段事件
- **WHEN** 调用方提供事件接收器并运行桌面任务
- **THEN** 运行时按实际生命周期顺序发布净化事件且最终返回一个确定的任务结果

#### Scenario: 无事件接收器运行
- **WHEN** 调用方以同步方式运行任务且未提供事件接收器
- **THEN** 运行时完成相同的工具调度与终态处理，不因缺少 UI 回调改变任务结果
