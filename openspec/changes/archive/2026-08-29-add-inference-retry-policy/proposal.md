## Why

当前推理客户端遇到 Ollama 短暂不可达、超时、限流、服务端错误或缺少有效正文的 HTTP 400 时会立即终止整个 ReAct 任务。桌面工具可能已经成功执行，此时一次瞬时服务抖动就会让会话进入 `error`，且用户无法从运行记录区分首次失败、重试过程和最终失败。

## What Changes

- 为主推理 `/chat/completions` 增加统一重试策略：首次请求失败后最多再重试 5 次。
- 只重试可能恢复的网络错误、超时、429、5xx，以及没有可判定永久原因的 HTTP 400；明确的请求格式、模型、鉴权和上下文错误立即失败。
- 使用有上限的指数退避与抖动，并遵守服务端 `Retry-After`；用户中断时立即停止等待和后续重试。
- 仅在响应尚未产生有效流式增量时重放请求；流已经输出正文、思考或工具调用片段后不自动重放，避免重复消息或工具动作。
- 重试不增加 ReAct 迭代、不追加重复会话消息、不重新执行工具；全部尝试耗尽后才把推理错误写入会话终态。
- 为每次重试及最终结果增加不含密钥、正文、截图和请求载荷的结构化运行事件与 TUI 进度提示。
- 增加可配置的最大重试次数，缺省为 5，允许设为 0 以关闭重试，并将取值限制在安全范围内。

## Capabilities

### New Capabilities

- `inference-retry`: 定义主推理请求的可重试分类、最多 5 次重试、退避、中断、流式安全边界与配置契约。

### Modified Capabilities

- `react-agent`: 推理异常仅在不可重试或重试耗尽后令 `think` 进入 `error`，重试不得改变图迭代与工具执行语义。
- `run-observability`: 记录每次模型重试及最终尝试次数，并保持敏感数据与大段内容边界。
- `session-store`: 重试期间保持会话消息幂等，最终失败检查点包含可读错误与重试耗尽摘要。

## Impact

主要影响 `src/max_gui/inference/client.py`、配置加载、Agent 事件回调、运行事件类型、TUI 状态展示、会话持久化测试及推理客户端测试。继续使用现有 Python、`httpx`、本地 JSON/JSONL 与 `uv`，不引入新的运行时依赖，不重试桌面工具，也不改变 provider 的请求协议。
