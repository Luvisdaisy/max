## Why

现有本地模型下载和单图基准命令已经具备最小实现，但“模型是否完整、输入是否可用、离线运行是否可复现”仍主要依赖运行时异常判断。下一阶段需要把 Qwen3.5-4B 的实际本地基准收敛为可预检、可诊断、可验收的离线工作流，以便在下载大体积模型前明确失败边界，并在完成后留下可审计证据。

## What Changes

- 为本地离线基准增加可执行的预检：验证受支持的 Qwen3.5-4B 目录、必要模型文件与图像输入，并在加载模型前给出针对性的修复提示。
- 将基准运行记录扩展为可复现的验收证据，明确记录离线约束、运行参数、加载时间、峰值显存、单图推理延迟和结果状态，同时不归档模型权重、图像内容或敏感路径。
- 统一基准失败路径：在创建归档后发生的预检、加载或推理失败都必须写入结构化结果和轨迹，并保持不触发网络下载。
- 补充面向开发者的实际执行顺序与验收标准：先完成显式下载，再以本地图片运行一次离线 4B 基准，并检查 `artifacts/` 中的证据。
- 增加针对预检、离线保证、归档字段和失败归档的自动化测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `local-model-benchmark`: 本地单图基准增加可验证的完整性预检、无网络执行保证、统一的失败归档与可复现验收证据要求。

## Impact

- 代码：`src/max_agent/cli.py`、`model_runtime.py`、`benchmark.py`，以及可能的模型配置辅助函数。
- 测试：模型运行时、基准与 CLI 测试将覆盖正常和失败路径。
- 文档：`README.md` 与 `tech-design.md` 将同步实际执行前置条件、命令及验收边界。
- 运行环境：实施阶段可能由开发者显式下载 Qwen3.5-4B 至 Git 忽略的 `model/`；基准过程只读取该本地目录和用户指定图像，并把诊断证据写入 Git 忽略的 `artifacts/`。
