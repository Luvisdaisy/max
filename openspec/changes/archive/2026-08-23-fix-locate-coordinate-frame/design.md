## Context

桌面截图同时存在三个坐标空间：桌面后端使用的逻辑像素、macOS 截图的物理像素，以及经 `prepare_image` 缩放后由模型看到的视图像素。当前截图的 `ViewFrame` 保存了三者之间的映射。OmniParser 在原图上检测，`project_and_draw` 可据该帧同时生成视图框和逻辑中心。

问题出在显式 `path`：它可以是历史截图、区域截图、工作区图片或已有带框图；这些路径通常不等于当前 `ViewFrame.image_path`。现有回退把原图尺寸当作逻辑桌面尺寸，仍将结果写入 `locate_hits`，导致高 DPI 下的编号可触发错误桌面输入。

## Goals / Non-Goals

**Goals:**

- 仅让能证明属于当前视图帧的检测结果产生可执行 `target_id`。
- 保留历史图与工作区图片的检测、编号叠加与模型阅读能力，但与桌面输入隔离。
- 让模型实际收到的叠加图尺寸与返回的 `view` 坐标一致。
- 明确 worker 使用本机文件路径这一运行边界。

**Non-Goals:**

- 不支持跨进程、跨机器或跨会话恢复历史截图到桌面坐标。
- 不改变 OmniParser 模型、置信度、NMS、OCR/caption 或编号上限。
- 不为外部图片推断显示器缩放率，也不增加多显示器支持。

## Decisions

### 1. 用帧身份而不是图像尺寸判断可执行性

仅当 `path.resolve()` 等于当前会话 `ViewFrame.image_path.resolve()` 时，定位结果才能带有桌面逻辑坐标并写入 `locate_hits`。同名、同尺寸、内容相同或带框副本都不能替代该身份判断。

显式传入其它路径时，工具仍返回带框图和图像内坐标，但标记为仅供观察；调用前清空当前 `locate_hits`，防止模型误用上一次的编号。

备选方案是保存每张截图的持久坐标帧。否决：截图文件可能被覆盖、跨会话时屏幕状态已改变，且会扩大会话数据与失效策略。

### 2. 叠加图在发送前确定最终视图尺寸

新增一个共享的图像尺寸决策：先对源图取得最终 `PreparedImage.width/height`，再按该尺寸画叠加图；发送层对已经声明为视图图的结果不得改变像素边长。若编码字节限制要求再次缩小，则重新生成叠加图并同步 JSON 坐标，而不是静默发送不同尺寸的图。

备选方案是在客户端重新缩放 JSON。否决：客户端没有检测框、逻辑中心与坐标帧上下文，容易让文本和命中表分叉。

### 3. worker 仅接收同机路径

配置解析时要求 `MAX_GUI_OMNIPARSER_BASE_URL` 的 host 为 loopback 地址。否则在首次 `locate` 前返回明确中文配置错误，不启动或请求远端服务。这样绝对路径不会被发送到无法访问其文件系统的端点。

备选方案是把图片字节上传到 HTTP worker。否决：这是可行的后续扩展，但会改变 worker 协议、输入限制与安全边界，超出本次修复。

## Risks / Trade-offs

- [模型尝试对历史框图直接点击] → 清空命中表并返回观察专用标记，提示先截图再定位。
- [PNG 叠加图接近字节上限] → 以最终发送尺寸为唯一来源，并用测试覆盖二次缩小分支。
- [用户已有非 loopback worker 配置] → 明确拒绝并说明该版本只支持同机 worker，避免静默失败。
- [会话恢复后当前帧对应的屏幕已经变化] → 保留现有的新截图/动作后截图清空命中表规则；本变更不放宽它。

## Migration Plan

1. 加入坐标帧与回注一致性测试，再实现路径分流与叠加图尺寸固定。
2. 更新工具描述和 `.env.example`，说明显式路径只用于观察、worker 仅本机。
3. 回滚时恢复现有的显式路径命中表写入；无需迁移会话格式。
