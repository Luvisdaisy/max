## Context

当前基线固定为 `main` 的 `27c46bc`。它已经有六个只读感知工具、统一注册表、一次只读模型工具选择、离线本地模型加载、仅用 mock 工具验证的 `observe → plan → guard → act → verify → recover` LangGraph，以及完成的 `improve-chat-console-experience`：Textual 控制台通过 `_interactive_dispatch`、`EventSink`、封闭 `ConsoleEvent`、`SessionStatus` 和单活动请求门禁提供稳定集成边界。

现有普通消息仍由 `ReadOnlyToolExplainer` 处理，最多调用一次只读工具；现有图会在规划前删除图像和文本，工具间也无法通过 JSON 安全串联 `PIL.Image` 与 OCR，因此不能驱动真实桌面任务。本变更在独立 worktree 中扩展运行时核心，并仅通过 `cli.py` 的依赖装配接入已经稳定的控制台协议。具体行为目标见 `proposal.md` 和本变更的七份 delta specs。

## Goals / Non-Goals

**Goals:**

- 让 `AgentRuntime` 成为任务生命周期和工具调度的唯一所有者，并以 LangGraph 实现受控的“模型最终文本或单工具调用”循环。
- 在不持久化截图的前提下把截图、OCR、视觉处理和多模态规划串成任务内存工作流。
- 默认允许受 Guard 管理的桌面控制，同时保证会话锁、窗口复核、Fail-safe、预算、确认和终态清理不可绕过。
- 以“任务栏可见记事本 → 置前 → OCR 读取 → 追加指定文本 → OCR 验证”为首个真实纵向验收。
- 提供前端无关的结构化运行事件与面向用户的任务结果，通过现有 Textual 事件接收器完成薄适配。
- 让 `WAITING_USER` 释放桌面控制资源并在下一条普通消息中安全恢复同一任务。

**Non-Goals:**

- 不修改 Textual widget、布局、命令菜单、滚动或输入体验；`chat-console-ui` 只更新运行时接入行为。
- 不修改 `console_core.py`、`console_frontends.py`、`local_llm.py` 或旧 `ReadOnlyToolExplainer`；聊天侧实现只允许调整 `cli.py` 的依赖装配和相关测试。
- 不增加任意脚本、Shell、文件删除、进程管理、剪贴板读取、网络请求或远程模型 Provider。
- 不自动保存记事本文档，不自动处理登录、验证码、身份确认或凭据。
- 不实现多任务队列、跨进程恢复、长期记忆或持久化截图回放。

## Decisions

### 1. 以 `AgentRuntime` 包装受控 text-or-tool 循环

新增前端无关的 `AgentRuntime.run(request, emit=None)`。外观负责创建任务级消息上下文、调用图、捕获未处理异常，并在 `finally` 路径强制执行输入清理、内存资源释放、锁释放和归档；LangGraph 是 `while` 循环的显式安全路由器，而不是预先决定工具顺序的固定业务流水线。

根本运行语义为：模型每轮只返回最终文本或一个结构化工具调用；工具结果加入同一任务消息上下文后再次调用模型，直到成功、等待用户、失败或中止。图实现为：

```text
INIT → REASON
         ├─ final_text ───────────────────────────────────────→ SUCCEEDED
         └─ tool_use → TOOL_GATE
                         ├─ user_interaction ─────────────────→ WAITING_USER
                         ├─ read_only → EXECUTE_TOOL → APPEND_RESULT ─┐
                         └─ side_effect → GUARD                       │
                                              ├─ needs_user ─────────→ WAITING_USER
                                              └─ approved → ACT
                                                  → OBSERVE_AFTER_ACTION
                                                  → VERIFY
                                                  → APPEND_RESULT ────┘
                                                        ↑             ↓
                                                        └─ RECOVER ← REASON

任一节点 → FAILED / ABORTED → CLEANING → ARCHIVING → END
```

首个 `REASON` 只消费系统提示、对话历史和用户消息，不预先截图、枚举窗口、运行 OCR 或获取桌面控制锁。普通问答可在第一轮以 `final_text` 结束；只有模型明确返回感知工具调用时才进入观察能力，从根本上修复当前每轮消息都调用 `observe_screen` 并夹带屏幕理解的问题。

所有循环边由模型轮次、工具调用、动作、格式纠正、恢复、单步时间、任务总时间和取消令牌共同限制。`WAITING_USER` 不是模型自由文本类型：模型通过公开的用户交互工具请求补充信息，或 Guard 因高影响动作要求确认；运行时返回明确问题和恢复标识，不在图内阻塞 UI 线程。进入等待前释放输入状态、图像、完整 OCR 和桌面锁；恢复时把用户答复加入同一消息上下文，旧坐标、批准和窗口绑定一律失效。

备选方案一是沿用固定 `observe → plan → guard → act → verify` 链路；它强制无关对话观察屏幕，也限制模型基于工具结果选择下一步，因此不采用。备选方案二是自由式 Agent Executor；它不能证明有副作用工具必经 Guard，也难以保证预算与异常清理，因此不采用。

### 2. 扩展工具描述与上下文，但保持注册表为唯一入口

每个工具声明稳定名称、输入模型、权限级别、允许阶段、默认超时、是否可恢复和描述。注册表调用扩展为接收只读 `ToolContext`，其中包含任务标识、取消令牌、预算视图、资源解析器和事件接收器；工具仍只返回结构化 `ToolReceipt`，不得修改全局图状态。

权限至少区分：

- `observe`：截图、OCR、窗口/UIA、视觉处理。
- `model`：本地结构化规划。
- `guard`：纯策略审批，不发送输入。
- `control`：唯一允许发送桌面输入的能力。
- `verify`、`recover`、`archive`：分别提供证据、建议和脱敏持久化。

注册表为每个工具额外区分“是否向模型公开”和“是否有桌面副作用”。模型只能选择当前轮次公开的工具；`guard`、`verify`、`recover`、`archive`、资源清理和锁管理属于运行时内部能力，不向模型公开。有副作用工具调用先转换为候选原子动作，经固定 `GUARD` 节点批准后才由 `ACT` 调用对应执行能力，模型工具调用不能直接发送桌面输入。

备选方案是让每个阶段直接导入实现。该方案会绕过统一权限、超时、回执和测试替换边界，因此不采用。

### 3. 使用任务级 `InMemoryResourceStore` 串联图像工具

截图和视觉处理不再把 `PIL.Image` 暴露给模型参数或可序列化状态，而是在任务级资源存储中写入对象并返回不可猜测的 `ResourceRef`。引用包含任务作用域和资源类型；注册表在调用 OCR、预处理、模板或 SoM 工具前解析引用。跨任务、已释放、错误类型和未知引用统一失败。

任务工作状态保存消息上下文、资源引用、完整 OCR 结果和当前轮模型响应；审计状态通过显式投影构造，只保留消息角色、工具名、稳定分类、尺寸、坐标、计数、哈希、简短行动摘要、错误码和验证证据。模型原始思维过程不进入任何状态。禁止继续用通用递归删除函数构造模型工具结果，因为它会误删下一轮所需数据或意外保留敏感字段。

备选方案是把截图写入 `artifacts/` 再传路径。该方案扩大敏感桌面数据的持久化范围并产生清理竞态，因此不采用。

### 4. 固定截图与 OCR 主观察管线，UIA 只做增强

当初始规划明确需要当前桌面证据后，每轮观察由编排器确定性执行：

```text
observe_windows + observe_screen
                  ↓ image_ref
             recognize_text
                  ↓
       StandardObservation + fingerprint
                  ↓
      按需 UIA / preprocess / template / SoM
```

进入桌面观察路径后的首帧默认执行全屏 OCR；后续先计算画面变化区域，仅对有效变化区域 OCR，并复用未变化区域中属于同一窗口和显示器的元素。窗口移动、DPI、前台窗口或捕获范围变化时放弃复用。OCR 模型在运行时生命周期中懒加载并复用，不在每个任务或每轮重新初始化。普通对话路径不会触发这条管线。

UIA 用于获取 `HWND + PID + exe path`、前台/焦点状态和可选 Text/Value 证据；UIA 失败不会替代或阻断截图与 OCR 主路径。若任务明确要求完整不可见文档文本，运行时可以请求 UIA TextPattern；记事本首个验收只以当前可见区域和追加结果为 OCR 判定依据。

备选方案是每轮优先遍历完整 UIA 树。它对可访问应用更快，但无法覆盖自绘界面，且元素坐标与用户实际画面可能不一致；因此只作为按需增强。

### 5. 模型会话以严格 text-or-tool 响应驱动每轮

新增 `invoke_model` 内部能力及最小 `AgentModelSession` 协议。它从当前选择模型的本地目录离线懒加载一个模型实例，任务内复用处理器与权重，并将系统提示、用户/模型消息、模型工具调用、对应工具结果和必要的内存多模态内容组织为模型输入。输出以 Pydantic 判别联合校验为 `FinalTextResponse` 或 `ToolUseResponse`；后者只包含一个工具名、一组参数和可选的简短审计摘要。

现有 `LocalChatRuntime` 继续负责模型目录选择及其旧聊天历史，本变更不修改它。CLI 适配通过可调用的“当前模型名称”解析器把选择传给 Agent 模型会话；模型选择成功变化时立即清除旧 Agent 模型会话和 `WAITING_USER` 任务，下一条普通消息按需加载新模型。所有普通消息均由 AgentRuntime 处理，其中无需工具的消息通过 `FinalTextResponse` 直接答复；内部系统提示、工具调用和工具结果不写入 `LocalChatRuntime` 聊天历史。

首次 schema 错误允许一次仅包含字段错误的纠正；第二次失败返回 `INVALID_MODEL_RESPONSE`。不从 Markdown、自然语言、Thought/Action 标签、多工具列表或最终文本旁的隐含 JSON 猜测调用。

备选方案是直接复用 `LocalChatRuntime.reply()`。它会把内部选择、工具结果与纠正提示提交到用户聊天历史，且现有接口不能表达严格工具响应，因此不采用。

### 6. 模型工具调用与 Guard 绑定最新观察

模型每轮只能返回一个工具调用。感知工具经 `TOOL_GATE` 验证后可直接执行；`activate_window`、`click`、`double_click`、`type_text`、`scroll`、`drag`、`key_chord` 和 `wait` 等有副作用调用被转换为一个 `DesktopAction`。工具输入 schema 先校验字段组合，Guard 再负责权限和环境校验。用户交互工具只产生 `WAITING_USER`，不执行桌面动作；`FinalTextResponse` 不属于工具调用。

Guard 以 `HWND + PID + resolved executable path` 识别目标窗口，标题只用于日志。模型元素坐标相对截图，Guard 根据显示器物理边界和 DPI 转换并验证命中。批准动作绑定候选动作哈希、窗口身份、物理坐标、状态指纹和短时有效期；执行工具在发送输入前再校验一次。

`key_chord` 使用静态白名单，首个场景只需要 `Ctrl+End`、方向键和 `Escape`。`type_text` 使用 Unicode 输入，不读取或写入剪贴板。`activate_window` 优先使用窗口身份进行受控激活；若必须点击任务栏按钮，则 Explorer 任务栏作为单独允许的系统表面审批，并验证动作后的前台窗口确为预期记事本。

普通未保存缓冲区追加不额外确认；保存、覆盖、发送、删除、支付、凭据、关闭未保存内容等进入 `WAITING_USER`。默认可控制电脑不改变这些策略。

### 7. 有副作用工具外围强制观察、验证与恢复

`execute_action` 只执行批准动作并返回动作哈希、时间、光标、输入长度摘要和结果，不判断目标完成。每次执行后图自动重新截图和 OCR，随后由 `verify_result` 按以下优先级判定：

1. 任务专用功能谓词；
2. 窗口身份与焦点；
3. OCR/UIA 目标证据；
4. 局部变化与状态指纹；
5. 仅在结构化证据不足时请求本地模型辅助。

记事本追加谓词检查：记事本已成为前台、焦点没有转移、重新 OCR 的可见文档包含新增文本。执行成功但证据缺失仍视为未完成。执行、动作后观察和验证被合并成一个净化工具结果追加到模型消息上下文；模型据此选择下一工具或返回最终文本。

`recover` 只返回“追加失败证据后继续模型循环”“重新观察”“允许一次审慎模型轮次”“等待用户”或“失败”建议。第一次无进展可重新观察，第二次允许一次审慎模型轮次，第三次等待用户或失败；恢复工具不得调用执行器，模型后续选择的任何有副作用工具都重新走 Guard。

普通对话的最终文本可直接完成。桌面任务一旦执行过有副作用工具，运行时只在最新目标验证成功时接受模型最终文本；否则把 `GOAL_NOT_VERIFIED` 作为工具结果加入消息上下文，并在剩余预算内继续或失败。这样模型负责表达最终答复，程序负责判定是否具备完成资格。

### 8. 终态清理采用不可跳过的外层保障

运行时进入任一终态或捕获异常后，按固定顺序：设置取消、停止新工具、释放鼠标与修饰键、清空任务资源、释放桌面锁、写入脱敏结果。清理步骤各自捕获错误，单项失败不得阻断其余清理；清理失败写入最终结果的独立错误列表。

`archive_run` 复用现有 `artifacts/` 约束，只记录配置、环境摘要、轨迹和结果。默认不归档截图、完整 OCR、输入文本、模型原始响应、密码或剪贴板。需要保留诊断证据的未来能力必须另行获得规格授权。

### 9. 通过现有控制台协议进行薄适配

`27c46bc` 已稳定 `_interactive_dispatch(artifact_root, runtime)`、`ChatHandler`、`EventSink`、`ConsoleEvent.tool(...)`、`ConsoleEvent.notice(...)`、`SessionStatus` 和 Textual 单活动请求门禁。适配只在 `cli.py` 装配：

1. 为交互会话创建一个 AgentRuntime，并让普通消息调用其运行或恢复入口；
2. 将运行时阶段映射为现有 NOTICE 事件，将工具开始、成功和失败映射为现有 TOOL 事件，绝不传递参数、回执、截图、OCR 或输入文本；
3. 将 AgentRuntime 结果中的 `response_text` 作为 `ChatHandler` 返回值，使 `dispatch_input` 继续产生现有 ASSISTANT 事件；已处理的 `FAILED`、`WAITING_USER` 和 `SUCCEEDED` 不通过异常模拟；
4. `/clear` 在现有可见记录与本地历史清理之外取消并清除挂起任务；成功 `/model` 切换使旧规划会话和挂起任务失效；`/status` 通过显式 `SessionStatus` 报告“本地、Agent Guard、受控桌面、无网络”的真实边界；
5. 保留 `console_frontends.py` 的单活动请求和焦点恢复逻辑，不修改 `console_core.py`、`console_frontends.py`、`local_llm.py`、Textual widget 或旧 `ReadOnlyToolExplainer`。

AgentRuntime 的桌面锁是 UI 门禁之外的第二层保护：UI 防止同一界面的重复提交，运行时锁防止任何调用路径并发发送物理输入。

## Risks / Trade-offs

- [默认具备桌面控制扩大误操作风险] → Guard、窗口双重复核、动作白名单、会话锁、Fail-safe、高影响确认和每步验证始终启用；模型不能直接选择控制工具。
- [OCR 比 UIA 延迟更高且可能误识别] → OCR 模型复用、后续帧局部识别、状态未变时复用结果，并以窗口身份和可选 UIA 证据交叉验证关键动作。
- [OCR 无法读取滚动区域外完整文档] → 首个验收限定当前可见内容；完整文档需求使用可选 TextPattern 或受预算滚动观察，不把不可见内容当作已读取。
- [任务内存保留截图和完整文本] → 资源引用任务隔离、终态强制释放、展示与归档使用显式白名单投影，不把工作状态直接序列化。
- [窗口激活受 Windows 前台限制] → 优先使用可验证窗口身份；激活失败返回可恢复证据，不通过重复盲点或提升权限绕过系统限制。
- [模型 text-or-tool 输出不稳定] → 判别联合 schema、工具输入 schema、一次格式纠正、低温生成和失败即停止；不解析自然语言中的隐含动作。
- [模型工具循环失控或消耗过多] → 分离模型轮次、工具、动作、纠正、恢复和总时间预算，并以等价工具参数、动作摘要和状态指纹检测循环。
- [运行时接入破坏现有控制台体验] → 只复用已经稳定的 dispatch、事件和状态接口，以回归测试锁定命令、单请求门禁、焦点恢复、Markdown 渲染和净化事件行为。
- [挂起任务长期占用桌面或复用陈旧坐标] → `WAITING_USER` 强制释放输入、资源和锁；恢复必须重新观察且旧审批与坐标全部失效。
- [普通对话被强制截图并泄漏无关屏幕上下文] → 初始规划不含视觉输入且不获取桌面锁；只有明确桌面目标可进入观察路径，并以零观察工具调用的回归测试锁定普通问答行为。
- [真实记事本测试可能修改用户数据] → 使用专用未保存测试缓冲区和唯一标记文本，默认不保存；自动测试使用受控 Win32 夹具，真实记事本仅在交互式授权会话手动验收。

## Migration Plan

1. 在基于 `27c46bc` 的隔离分支实现数据契约、工具元数据、任务内存资源和纯 mock 生命周期测试，不先修改控制台实现。
2. 实现严格的最终文本/单工具调用模型响应和任务级消息上下文，再接入截图、窗口发现、OCR 与观察组合，使用合成图像验证多轮只读工具循环，不发送真实输入。
3. 实现工具门、Guard、桌面执行、动作后观察、验证、恢复、清理和归档能力；先以 mock 输入适配器覆盖所有路径，再以现有受控 Win32 探针验证真实输入。
4. 完成独立 `AgentRuntime` 集成测试、直接文本答复、多轮工具调用、`WAITING_USER` 释放与恢复，以及记事本夹具验收，确认默认控制仍只能通过 Guard。
