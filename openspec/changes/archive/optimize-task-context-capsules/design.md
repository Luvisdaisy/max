## Context

`AgentRunner.run` 当前会从 `session.messages` 重建 `AgentState.messages`，每次 `think`
将该列表完整传给 `to_chat_messages`。编码器已把图片限制为最后一张，但仍会传输历史用户
文本、助手正文、tool 调用及工具输出；同一会话内的后续任务会重复携带这些内容。会话 JSON 和
run JSONL 同时承担恢复、TUI 回放和审计职责，不能因为减少模型输入而丢失。

OpenAI 兼容工具协议要求：同一未完成任务内，assistant 的 `tool_calls` 与其后的 `tool`
消息必须以 `tool_call_id` 配对。因此裁剪单位不能是单条消息，而必须是“任务”以及其中完整的最近
调用链。桌面安全边界仍要求动作前后基于新截图核验，不能以历史摘要代替当前观察。

## Goals / Non-Goals

**Goals:**

- 为新用户任务构建确定的、任务级最小模型上下文。
- 在任务内保留足以继续 ReAct 和满足 tool 协议的消息链，同时仅发送最新有效截图。
- 将可恢复的任务语义与全量会话历史分开持久化，并以可观测指标验证裁剪效果。
- 保持旧会话和中断 checkpoint 可读取，且不降低现有桌面动作核验要求。

**Non-Goals:**

- 不修改工具 schema、坐标换算、批准策略或截图采集频率。
- 不自动概括或重新生成旧模型正文，不引入向量检索、外部数据库或新网络服务。
- 不删除、轮转或压缩会话、截图和运行日志。
- 不改变用户显式上传附件的保留语义；本变更只决定模型请求上下文。

## Decisions

### 1. 以任务胶囊取代会话消息作为默认推理输入

新增内部 `TaskContext`，持有 `task_id`、原始用户指令、任务状态（运行／完成／失败／中断）、
当前计划与子任务、最后动作及核验结论、近期动作摘要和最新截图引用。开始新的普通用户输入时，
创建新胶囊；已有 `interrupted` checkpoint 的恢复沿用其胶囊与 `run_id`。

每次 `think` 从胶囊构造输入：固定 system、当前任务的用户指令、最近完整 tool 调用链、以及最新
观察。任务完成后，会话仍追加全量消息，但下一条独立用户指令默认从新胶囊开始，不再回放旧任务。

备选方案是按消息数量滑动窗口。否决原因：窗口可能截断 `tool_calls`／`tool_call_id` 配对，也无法
区分上一任务的冗余文本与本任务的必要上下文。

### 2. 以结构化近期动作摘要限制增长

胶囊只保留最近 6 条已完成的工具动作。每条包含工具名、截断后的参数、成功／失败、是否取得新图、
以及简短结果或核验结论；不包含图片字节、OCR 全文或 `keyboard_type` 输入正文。超出上限的动作仅
存在会话和 run 日志。若需要继续同一任务，摘要滚动更新；最近仍未配对的 assistant tool call 与
tool result 则整体保留，不能被上限拆开。

选择固定 6 条而非配置项：当前为单用户 CLI，先提供稳定且可测试的默认值，避免扩大运行时配置面。

### 3. 最新观察优先，并显式处理无图与指代歧义

模型请求至多附一张图片，优先级为当前任务最新成功 screenshot、否则用户本任务最新有效附件；
没有有效图片时发送文字状态并遵守现有“先 screenshot”契约。新的任务若输入是“继续”“重试”等
延续关键词且会话存在中断任务，恢复该胶囊；其他输入一律新建任务。

若新指令依赖旧目标而最新截图和胶囊任务状态不足以确定目标，系统不借用旧任务全文；模型必须先
截图、定位或向用户澄清。备选是把上一任务全文附到新任务，否决原因是会破坏 token 上界。

### 4. 存储与推理上下文分离，并保持向后兼容

`Session` 增加可选的任务胶囊快照，仅用于中断恢复和新任务边界判断；全量 `messages`、视图帧、
定位表、checkpoint 和 run JSONL 原样保留。旧会话缺少任务胶囊时按“没有可续接任务”加载；旧的
中断 checkpoint 保持现有恢复路径，并在第一次新的持久化时写入新字段。

### 5. 用摘要计数验证优化，不记录敏感内容

每个 `model.started`／`model.completed` 事件写入本请求的消息数、内联图片数、近期动作数，以及已知
的 `prompt_tokens`。被裁剪的历史只记录数量，不复制正文、截图路径、截图字节、OCR 或键盘输入。
运行终态汇总任务内累计已知 token 用量和裁剪计数；未知用量仍不得伪造为 0。

## Risks / Trade-offs

- [跨任务指代失去必要语义] → 对中断任务保留可续接胶囊；其它歧义场景要求重新观察或澄清，不猜测。
- [裁剪破坏工具调用配对] → 以完整调用链为原子单位，编码前校验每条 tool 消息都具有其 assistant 调用。
- [最新截图缺失或陈旧] → 只使用存在的成功截图；无图时强制回到截图工具路径，动作工具仍受现有 gate 限制。
- [任务摘要包含敏感键入内容] → `keyboard_type` 只记录已发生这一事实和字符数，不保存正文。
- [旧 checkpoint 无新字段] → 保持既有 checkpoint 恢复，首次安全写回后补充可选字段；不做批量迁移。

## Migration Plan

1. 先引入纯内部的数据结构和兼容读取，现有会话文件无需迁移。
2. 在新任务与恢复路径启用胶囊构造，并以新增测试覆盖工具协议、截图优先级和上下文上界。
3. 通过运行事件的已知 `prompt_tokens` 与裁剪计数观察效果；出现兼容问题时，回退为从当前任务的
   全量消息重建，但继续保留全量会话和日志。

## Open Questions

无。近期动作历史固定为 6 条；任务延续仅限显式恢复中断任务。
