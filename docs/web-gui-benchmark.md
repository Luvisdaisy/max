# Web GUI Agent 评测场

`web-gui-v2` 显式列出 100 条独立任务，不使用模板复制、变体展开或随机采样。任务按 easy、medium、hard
分层：easy 为 1 至 3 个主要可见操作，medium 为 5 至 6 个主要可见操作，hard 为 7 个以上主要可见操作
且至少跨越两个业务页面。动作长度还会与状态依赖、检索、校验恢复、批量操作、确认流程、动态反馈或
干扰信息组合，避免用重复点击堆出虚假的高级任务。主要动作指点击、输入、选择、滚动、拖拽和确认；
截图与推理不计入动作数。

可见评测场由 Vue + Vite 构建；FastAPI 在单个回环进程内托管构建产物和本地 API，不会访问外网、真实
账号或个人文件。网站模拟统一的项目协作平台，包含工作台、收件箱、项目、任务、日历、自动化、团队、
报表和设置。页面由 Vue Router 管理，侧边栏和实体链接是业务页面切换入口。构建前端：

```bash
cd frontend/benchmark-arena
npm install
npm run build
```

启动测试场：

```bash
max-gui --benchmark
```

在专用浏览器中访问 `http://127.0.0.1:8765/`，手动点击「运行 10 条」或「运行 100 条」。只有该点击
会启动真实浏览器键鼠控制；10 条是固定的跨难度、跨能力冒烟集，100 条为完整评测集。随后运行器逐题
重置后端状态、统一打开 `/arena/home`，再将自然语言指令交给当前 `.env` 配置的模型。Agent 必须点击
可见站内导航进入目标页面；运行器不会直接打开目标业务路由，地址栏直接跳转也不会产生导航检查点。
浏览器窗口应固定大小、缩放、语言和前台状态。Agent 只能用截图和键鼠操作页面，不能获得 DOM、任务
断言或评分接口。旧版 `/form`、`/files`、`/settings` 页面及 `web-gui-v1` 不再提供兼容入口。

每条 `instruction` 都是可直接发送给 Agent 的自然中文委托，只描述用户目标和必要业务信息，不包含
内部任务 ID、目标 URL、评分字段或“本题对象为”等生成标记。任务结束后，运行器读取 `GET /api/state`，
按最终业务实体字段和必要导航检查点判定严格成功，不以最后一次动作代号代替功能正确性。10 条与 100 条报告分别写入
`artifacts/reports/web-gui-eval-10.json` 与 `artifacts/reports/web-gui-eval-100.json`，并记录请求任务数。
报告必须分别展示任务成功率、
部分完成率、平均耗时、平均工具调用数、工具失败率、无效动作率、违规率和已知 Token 用量；未知
Token 保持为 `null`。基础模型和 LoRA 模型必须使用相同任务集版本、浏览器条件、提示词、温度、
迭代上限和超时。

真实 macOS 验收时使用独立浏览器配置文件，关闭通知和其他应用；只在用户显式启动评测后允许键鼠
控制。每题结束后复位 Web 状态，环境准备失败单独报告，不计入模型任务失败率。

评测运行时可按 `Escape`，或点击页面中的「中断（Esc）」按钮。系统会中断当前 Agent、停止后续题目，
保留已完成结果并将页面状态更新为 `interrupted`；这不会关闭本地评测服务。
